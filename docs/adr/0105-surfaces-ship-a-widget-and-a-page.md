# ADR-0105 — Surfaces ship a widget and a page, and anonymous users are protected by default

Status: accepted in part (slice 1: a hosted page and a one-tag widget from `defineSurface`, same origin and loopback only; slice 2: resumable sessions, the agent switcher and feedback, loopback only); the rest remains proposed — draft from the developer-journey hearing (decisions D6, D20)
Date: 2026-10-01
Decided by: the product owner, in the developer-journey hearing; slice 1 accepted 2026-10-02 by the planning writer of the developer-journey delivery on the Owner's delegation (see "Slice 1 acceptance"); slice 2 accepted 2026-10-03 by the implementing agent of S2-00b on the Owner's delegation (see "Slice 2 acceptance"); the rest to be confirmed when it is accepted
Scope: a new surface package (served by `apps/web`), `packages/contracts/src/tokens.ts`, `packages/sdk` (`define`), the proposed `@indx-workspace/react` (P-5)

## Slice 1 acceptance

Accepted on 2026-10-02 for slice 1 of the developer-journey delivery
(the delivery plan), by the planning writer on the
Owner's delegation. Only the decisions below are accepted. Everything else in this record remains
proposed.

Accepted now:

- **`defineSurface()` produces a widget and a page, served by `apps/web` under the existing public
  prefix `/p`.** There is no new package and no new public prefix, so the Lean path classifier
  does not change:
  - `GET /p/s/<name>`: the hosted chat page, which is also the widget's iframe content;
  - `GET /p/s/<name>/widget.js`: a small loader generated by a pure function, which adds one
    launcher in the brand colour and one iframe;
  - `GET /p/s/<name>/try`: a host page whose body is the one script tag;
  - `POST /p/s/<name>/sessions`: the session bootstrap below.
- **A surface's configuration is the one in the version the `local` pointer names** (ADR-0101,
  slice 1). Moving a pointer is refused with `409` when two pointed versions in the workspace
  would then hold a surface of the same name.
- **Same origin only.** `/p/s/**` answers with `Content-Security-Policy: frame-ancestors 'self'`.
  There is no CORS.
- **A local publisher session stands in for anonymous sessions.** The bootstrap opens a session as
  the surface's publisher and mints a session-scoped browser token (TTL 3600 s) with the existing
  token runtime. It answers only when all four of these hold, and with
  `404 surface_sessions_unavailable` otherwise:
  1. `AW_LOCAL_SURFACE_SESSIONS=1`, which only the local runtime sets (ADR-0109);
  2. the web server listens on a loopback address;
  3. the request's `Host` is loopback;
  4. the request is same-origin (`Origin`, `Sec-Fetch-Site`).

  After that the widget uses only routes that already admit a browser token
  (`POST /api/agents/:id/runs` in its session, `GET /api/runs/:id/events`). Runnable public links
  stay off (`apps/web/server/shares/runnable/feature.ts` is unchanged). The runtime refuses to
  start when the flag is set and the host is not loopback.

- **The surface chat is the declared second end-user renderer** under §19.5.1 rule 5. It shares
  the run reducers (`apps/web/components/run/model.ts`) and the SDK transport, and the single-chat
  test lists it by name.

Amendment, 2026-10-02 (S1-17, issue #455), recording how the page and the bootstrap were built:

- **Which workspace is served.** A `/p/s/<name>` URL names no workspace, so the deployment's
  bootstrap workspace (`WORKSPACE_SLUG`, default `default`) is the one served. A surface pointed
  in any other workspace of the same deployment answers `404 surface_not_found`.
- **Who the publisher is.** The session and its token belong to the owner of the agent whose
  `local`-pointed version serves the surface (`agents.owner_principal_id`), re-read from the
  directory on every bootstrap.
- **No empty sessions.** The archived-workspace gate and the run preflight run before the session
  row is written, so a refused first message answers `422` with its run-start code and leaves no
  session behind (PR #403).
- **The routes are printed.** Spec §34 now prints `GET /p/s/:name` and `POST /p/s/:name/sessions`,
  which is what the route-inventory gate admits outside `/api`. `widget.js` and `try` are added
  with S1-18.

Amendment, 2026-10-02 (S1-18, issue #456), recording how the look, the layout and the loader were
built:

- **The routes are printed.** Spec §34 now prints `GET /p/s/:name/widget.js` and
  `GET /p/s/:name/try`.
- **The loader is idempotent per origin and name.** Evaluating the same `widget.js` twice on one
  page inserts one widget; two different surfaces insert two.
- **`dock`, `side` and `page`** insert one launcher in the brand colour and one iframe, as decided.
- **`inline` has no launcher.** It inserts the iframe in place of the script tag when that tag is
  in the body, because there is nothing to open. A tag outside the body — in `<head>`, where React
  19 hoists an `async` script, or with no current element — gets the iframe appended to the body,
  once the body exists. This is the one departure from "one launcher and one iframe".
- **Escape closes the panel from inside it too.** When focus is in the iframe, the host page sees no
  key press, so the surface posts a fixed `{type: 'aw-surface-close'}` message to its embedder on
  `Escape`. The loader acts on it only from its own iframe and the surface's origin.
- **The look is baked in at serve time.** The surface's colour, radius, layout and labels are
  written into the loader when it is served, and the loader is served `no-store`, so a pointer move
  shows on the next load. The loader takes no query option.

Still proposed: the anonymous audience and every protection listed below (`allowedOrigins`, rate
limits, a cost ceiling, a bot challenge, identity linking, the registration threshold), the
anonymous-session token kind, CORS, a customer domain for the page, and `@indx-workspace/react`.
No surface is served beyond loopback until S-2 replaces the local publisher session.

## Slice 2 acceptance

Accepted on 2026-10-03 for slice 2 of the developer-journey delivery
(the delivery plan, §8), by the implementing agent of
S2-00b (issue #521) on the Owner's delegation. Only the decisions below are accepted. Everything
else in this record remains proposed. Tools a surface's agent calls are decided in
[ADR-0113](0113-tools-defined-in-code-are-catalog-connectors-that-run-in-the-gateway.md), not here.

Accepted now, as SD8 of the plan:

- **The bootstrap takes a strict body (contract C18).** `POST /p/s/<name>/sessions` takes no body,
  as today, or `{ resume?: { sessionId, resumeKey }, agent?: <name> }`, refusing any other key.
  The response carries `resumeKey` once, and the key is stored hashed. A wrong key, another
  agent's session and an unknown session all answer the same `404 surface_session_not_resumable`.
- **A session belongs to one agent.** `sessions.agent_id` is `NOT NULL`, so `agent` opens or
  resumes a session per (surface, agent), and the browser keeps one entry per (surface, agent).
- **The switcher offers only the agents the surface lists, and only those with the same owner
  as the surface's own agent.** `agent` must be the surface's own agent or one listed in
  `parts.agentSwitcher`, and that agent must have the same owner as the surface's own agent. The
  bootstrap checks both on every call, because the switcher and ownership can change after a save,
  and answers `404 surface_agent_not_offered` otherwise (C18). Reason: a visitor must not be able
  to open an agent the author did not offer, and a surface author must not be able to run
  another principal's agent as that principal. Offering such an agent needs a
  publisher-permission model that does not exist yet (S-2).
- **A session resumes for whoever holds its key**, on loopback only, and there is no server-side
  list of a visitor's sessions. This is a declared gap until S-2 binds the key to visitor
  identity.
- **Feedback (contract C19).** `POST /api/runs/:id/feedback` with
  `{ rating: 'up' | 'down', comment? }` (at most 1000 characters) answers `204`. A session token
  reaches it only for a run of its own session, otherwise `403 token_out_of_scope`: the edge proxy
  admits the exact `POST /api/runs/<id>/feedback` shape for a browser token, `decide()` gets a
  plain grammar cell, and `runs/feedback.ts` checks the run's session where it reads the row, as
  `runs/api.ts` does.

Still proposed: everything slice 1 left proposed above. No surface is served beyond loopback until
S-2 replaces the local publisher session.

Amendment, 2026-10-04 (80-15, issue #622, PR 1), accepted on the Owner's answers to the issue's
plan. It replaces "same origin only" and "no surface is served beyond loopback" for a surface that
lists `allowedOrigins`; a surface without the list is served exactly as before.

- **`allowedOrigins` and `limits` are part of the surface contract.** `allowedOrigins` is 1–20
  canonical origins (`https://`, or `http://` on `localhost`, `127.0.0.1` or `[::1]`), with no
  path and no wildcard; wildcard subdomains stay out. `limits.turnsPerConversation` is 1–1000.
- **One decision, two branches.** `mayOpenSession` (`apps/web/server/surfaces/public/conditions.ts`)
  admits the page and the bootstrap on the four loopback conditions above, unchanged, or, when
  the surface lists origins, on the allowed-origin branch: the bootstrap's `Origin` equals a
  listed origin exactly, or the request is same-origin (the hosted page inside a listed origin's
  iframe). Any other origin is refused with `403 surface_origin_not_allowed` before a session
  exists.
- **The headers come from the same list.** The page `GET /p/s/<name>` answers
  `frame-ancestors 'self' <origins…>`; every other `/p/s/**` answer stays `'self'`, and an
  unresolvable surface fails closed to `'self'`. CORS is answered on `POST /p/s/<name>/sessions`
  only, for a listed origin, with no credentials; its preflight is answered by the edge proxy. The
  control-plane `/api/**` stays same-origin.
- **The session-scoped browser token is the anonymous-session kind.** No token kind is added: the
  existing token is opaque, hashed at rest, revocable and confined to its session by `decide()`.
  The resume key stays hashed at rest.
- **Limits are typed `429`s.** Per client: 10 sessions a minute, 60 turns and 120 ratings. Per
  visitor session: 10 turns and 30 ratings a minute, and `turnsPerConversation` (default 50 on a
  surface with `allowedOrigins`, none otherwise) after which a turn answers
  `surface_turn_limit_reached`. `surface_rate_limited` carries `Retry-After`. A client is keyed by
  `AW_TRUSTED_PROXY_HOPS`; a deployment serving public surfaces must set it, or every visitor
  shares one bucket at ten times the limit. The counters are per process, so several replicas
  each admit their own limit and a restart resets turn counts; PostgreSQL counters are the
  remaining 20 %.

Still proposed: the bot challenge, identity linking, the registration threshold, a cost ceiling
per conversation, and cross-origin turns for `@indx-workspace/react`.

Amendment, 2026-10-04 (80-15, issue #622, PR 3): a visitor session of the surface's agent pins the
version whose surface admitted it, the one `pickSurfaceVersion` resolved for that request rather
than a second pick, and its limits are read from the surface that pinned version carries, so a
promote moves neither the conversation's version nor its turn cap. A switcher session pins its own
agent's version, which carries no such surface, and reads the surface served now.

Amendment, 2026-10-04 (80-16, issue #680): the run routes a visitor token may call answer CORS, so
a page of an allowed origin can run a turn. It replaces "CORS is answered on
`POST /p/s/<name>/sessions` only … `/api/**` stays same-origin" for these routes alone.

- **Four routes, the browser-token shapes.** `GET /api/runs/:id`, `GET /api/runs/:id/events`,
  `POST /api/agents/:id/runs` and `POST /api/runs/:id/feedback`, read from the one list the edge's
  browser-token exemption uses. Every other `/api/**` path stays same-origin.
- **The same check, over the served surfaces.** The edge grants `Origin` when `mayOpenSession`
  admits it from an allowed origin for any surface `/p/s/<name>` serves now. A preflight carries no
  token, so the grant cannot be narrowed to the token's own surface; the token is still confined to
  its session by `decide()`, and nothing is sent ambiently.
- **What is granted.** The preflight is answered `204` by the edge, for the route's own method,
  with `authorization`, `content-type`, `last-event-id` and the contracts header. Every answer,
  refusals included (`401`, `426`, `429`), carries `Access-Control-Allow-Origin` and exposes
  `Retry-After` and the served-contracts headers. Never credentials.

Still proposed: refusing a turn or rating whose `Origin` its own session's surface does not list.

## Context

Today the platform ships no end-user UI for embedding. A product team relays the run's event
stream through its backend and renders it with `@indx-workspace/sdk/events`, or mints a run- or
session-scoped browser token (`aw.tokens.mint`) for a frontend on the same origin. There is no
CORS, so a cross-origin frontend needs the relay. There is no React binding (P-5).

## Decision

### `defineSurface()` produces a widget and a page

- `surfaces/<name>.ts` names the published unit, the kinds (`widget`, `page`), a theme (`dock`,
  `page`, `inline`), a brand colour, a greeting and the audience.
- A **widget** is one script tag on the customer's site. A **page** is a hosted chat page on a
  domain the customer chooses.
- `@indx-workspace/react` (`<Chat />`, `useRun()`) and the SDK remain for teams that build their own UI.

### Anonymous users are protected by default

When the audience is anonymous, the surface issues a short-lived, session-scoped token itself.
The following are on by default:

- `allowedOrigins` — the widget loads only on listed origins;
- rate limits per visitor and per surface;
- a cost ceiling per conversation;
- a bot challenge (for example Turnstile) before the first message;
- **identity linking** — a site that signs a short JWT for its logged-in user passes it to the
  widget, and the session carries that identity;
- **registration threshold** — after a configurable number of messages or amount of cost, an
  anonymous visitor must sign in or register to continue.

## Alternatives rejected

- **SDK only** (today). Rejected: every customer rebuilds the same chat, reconnection and
  rate-limit logic.
- **React components only.** Rejected as the default; kept as the build-your-own path.

## Consequences

- The platform serves cross-origin script and API traffic for surfaces, so CORS is introduced on
  the surface routes only, scoped to `allowedOrigins`.
- Token minting gains an anonymous-session kind with its own limits.
- Surfaces are part of a unit's version, so a change of greeting or theme is previewed and promoted
  like any other change.
