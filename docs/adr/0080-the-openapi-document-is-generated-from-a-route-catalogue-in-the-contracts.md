# ADR-0080 — The OpenAPI document is generated from a route catalogue in the contracts

Status: accepted
Date: 2026-09-29
Decided by: the implementer of SDK migration unit 13 (issue #245)
Scope: `packages/contracts/src/routes.ts`; `scripts/docs/generate-openapi.mjs`;
`docs/sdk/site/openapi.json`; `tests/docs/openapi.test.ts`; `package.json` (`docs:generate`,
`docs:check`, three devDependencies); spec `docs/sdk/03-sdk-design.md` §3.7

## Context

The wire contract existed only as Zod schemas (P-7). A consumer in another language had nothing
to generate a client from, and nothing in the contracts said which schema a route is parsed with:
the SDK's resource clients knew, one call site at a time. 03 §3.7 already ruled that OpenAPI is
never the source of truth.

## Decision

### D1 — The contracts carry a route catalogue

`@agent-workspace/contracts/routes` exports `API_SCHEMAS` (every schema a route names, keyed by its
exported name), `API_ROUTES` (one entry per public `METHOD /path`: `operationId` — the SDK operation
name —, `tag` — the SDK family —, `summary`, the request body and one body per success status) and
`API_ROUTE_EXCLUSIONS`. The exclusions are of two kinds, and only these two: browser journeys
(04 §1: setup, OIDC sign-in, `/p/*`) and private runner routes (the transcript `POST`/`DELETE`
and the seven ENG-06 `state-entries`/`state-streams`/`state-blobs` routes, whose only client is
`apps/runner` with the signed per-run token — `apps/web/server/sessions/state-api.ts`, 04 §5.11).
Issue #245's "minus 04 §1's exclusions" is read as "minus the routes that are not the customer
surface": publishing a runner route would hand every generated client a call it must not make,
with a credential it does not hold. An entry may also carry `security` when its credential is not
the default (`none`, `session-cookie` or `invitation-identity`, mirroring the public and
identity-only routes of the authorisation matrix). A body names
schemas by key, so a misspelt name is a type error. A body the contracts do not yet describe is
declared `json-undescribed` and emitted as untyped JSON rather than guessed; typing it means adding
the schema to the owning module.

### D2 — The emitter reads the source and Zod converts

`scripts/docs/generate-openapi.mjs` imports the catalogue's TypeScript source with Node 24's type
stripping, mapping the emitted `./x.js` specifiers to `./x.ts` through a resolve hook, so
`pnpm docs:check` needs no build (it runs before the build in CI). Each schema is converted by
Zod's own `toJSONSchema` (draft 2020-12, the OpenAPI 3.1 dialect) into `components.schemas`, once
per direction when input and output differ; `$defs` are hoisted into components. Every operation
has the standard envelope (`ApiProblemSchema`) as `default`, `400` (which includes
`contracts_version_malformed`), `426 contracts_version_unsupported` with its `Upgrade` header,
the optional `x-agent-workspace-contracts` request header (a request without it is served) and
the `x-agent-workspace-contracts` / `-minimum` served-range response headers of ADR-0078. The
header names and the two statuses are imported from `@agent-workspace/contracts`
(`CONTRACTS_VERSION_HEADER`, `CONTRACTS_MINIMUM_VERSION_HEADER`,
`CONTRACTS_VERSION_PROBLEM_CODES`), so the document cannot drift from the edge; the run event stream is `text/event-stream`, with its frame schemas listed in an
`x-agent-workspace-frames` extension because OpenAPI 3.1 has no item schema for a stream. Keys
are sorted recursively and the file is two-space JSON with LF and a trailing newline.

### D3 — Checked like the reference pages

The document is `docs/sdk/site/openapi.json`, written by `pnpm docs:generate` and compared by
`pnpm docs:check`, like ADR-0054's reference pages. The Reference tab renders it through
Mintlify's OpenAPI support, and `llms.txt` lists it under Optional.
`tests/docs/openapi.test.ts` holds the catalogue equal to `tests/route-declarations/**` minus the
exclusions in both directions, allows only the two exclusion kinds, holds the routes marked with
`security` equal to the authorisation matrix's public and identity-only routes, freezes the
`json-undescribed` bodies so their list can only shrink, validates the document against the OpenAPI 3.1 schema, renders it
twice, type-checks a client generated by `openapi-typescript` against `GET /api/me`, and runs an
`openapi-fetch` call whose answer is checked against the document's own `MeResponse` component.

### D4 — Three devDependencies, test and tooling only

`@seriousme/openapi-schema-validator` (MIT) validates against the official 3.1 schema;
`openapi-typescript` (MIT) and `openapi-fetch` (MIT) are the off-the-shelf generator and client
the acceptance test uses. None is a runtime dependency of any package.

## Consequences

- A route that lands without a catalogue entry fails the test, so the document cannot silently
  lose a route; a contract change reaches the document on the next `pnpm docs:generate`.
- Most create and update request bodies are untyped JSON until their schemas move into the
  contracts; `building/http-api.mdx` says so.
- Publishing the document with the package is unit 14's (#246).

## Alternatives considered

- **Emit from the SDK's call sites.** Rejected: the SDK is a consumer; the route ↔ schema mapping
  is part of the contract, and routes without an SDK method would be missed.
- **A third-party Zod-to-OpenAPI library.** Rejected: Zod 4 converts to JSON Schema itself, and
  such a library would ask the contracts to annotate every schema.
- **Read `dist/` instead of the source.** Rejected: `docs:check` runs before the build in CI.
