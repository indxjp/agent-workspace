As-Is to To-Be change map

AS-IS
API keys fall back to the oldest Owner and resource ownership is a human FK.
→
TO-BE
WorkspacePrincipal represents Membership or APIKey and owns resources directly.
→
WHY / MIGRATION
Eliminates impersonation. Backfill human principals, dual-read ownership, then require principal FKs.
AS-IS
Deleting an Agent cascades Sessions, Runs, transcripts and usage evidence.
→
TO-BE
Agent archives; Session/Run keep nullable source references plus immutable execution snapshots.
→
WHY / MIGRATION
History survives configuration lifecycle. Backfill snapshots before changing FK actions.
AS-IS
Model/runtime credential ownership depends on names and separate pool compensation.
→
TO-BE
Typed connection rows hold direct Secret FKs; encryption participates in one database unit of work.
→
WHY / MIGRATION
Database-enforced ownership and no crash-window orphan.
AS-IS
Share subject is polymorphic text and the client supplies authoritative content.
→
TO-BE
Typed subject loader creates a versioned, hashed, immutable ShareSnapshot server-side.
→
WHY / MIGRATION
Permission and published representation refer to the same canonical subject.
