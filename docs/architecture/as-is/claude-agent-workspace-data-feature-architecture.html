Actual architecture versus recommended direction

Actual

  • Next.js routes call configured process-global runtimes and stores.
  • register.ts opens infrastructure and wires almost every domain.
  • A durable Run row is followed by an untracked in-process launcher.
  • Runner-manager owns session affinity in process-local Maps.
  • File bytes/catalogs and secret/domain rows use compensation across stores.
  • Route error and logging behavior varies by feature.
Direction
→

Recommended

  • Explicit application container/request context with feature-owned composition modules.
  • DB-backed run ownership lease, retry and stale-run reconciler.
  • Persistent runtime allocation/cleanup policy and authenticated runner transport.
  • Transactional outbox/reconciliation for cross-store changes and audit events.
  • One HTTP error/request-context boundary and one specified SSE parser.
  • Domain/application records separated from persistence and wire types.
