- **You will:** store, list, rotate and remove the workspace's credentials without ever reading one back.
- **You will learn:** the name rules, why a value travels only once, and why a secret a connector or model connection uses cannot be deleted.
- **You need:** an API key for the workspace; only an Owner may remove a secret.

`aw.secrets` stores a workspace's arbitrary credentials — provider API keys, tokens, anything an
agent or a connection needs at runtime — under a name. It wraps `/api/secrets/**`
(API specification §5.5). Source: `packages/sdk/src/resources/secrets.ts`, contract:
`packages/contracts/src/secrets.ts`.

**What you can do**

- [Store a credential](#create) with `aw secrets create --name <NAME> --value-stdin`
- [List what is stored](#list), names and metadata only
- [Rotate a value in place](#replace), keeping its name and id
- [Remove a secret nothing references](#remove)

In an agent's files, an API tool names its token with `secret('NAME')` and `aw dev` reads the value
from its own environment; see
[Keep the API token out of your code](/guides/tools-from-code#keep-the-api-token-out-of-your-code).
The two are separate: a `secret('NAME')` is never looked up in `aw secrets`, and `aw secrets` holds
the workspace secrets that connectors and model connections made through the API reference. A name
the local runtime reserves (`PORT`, `PATH`, any `AW_` name) is refused by both.

<Warning>
  Secrets are **write-only** over HTTP. A value travels once, in a `create` or `replace` request
  body, and never comes back — there is no field for it anywhere in `SecretResource`, no `GET
  /api/secrets/:id`, and the schema is `.strict()`, so a body that tried to carry one would be
  refused rather than silently dropped.
</Warning>

A secret's metadata is a `SecretResource`:

```ts title="illustrative" claim="illustrative"
interface SecretResource {
  id: string;
  name: string; // ^[A-Z][A-Z0-9_]{0,127}$, e.g. ANTHROPIC_API_KEY
  algorithm: string; // the envelope cipher, for audit — never enough to read the value
  masterKeyId: string; // the key that wrapped this secret's data key
  createdAt: string;
  updatedAt: string;
}
```

`SECRET_NAME_PATTERN` is `/^[A-Z][A-Z0-9_]{0,127}$/` (uppercase letters, digits and underscores,
starting with a letter, 1–128 characters); `SECRET_VALUE_MAX_LENGTH` is `64 * 1024` (65 536) code
units.

## Complete example

```ts title="secrets-example.ts" claim="compile"
import { createClient, ApiProblemError } from '@indx-workspace/sdk';

const baseUrl = process.env.AGENT_WORKSPACE_URL;
const apiKey = process.env.AGENT_WORKSPACE_API_KEY;
if (baseUrl === undefined || apiKey === undefined) {
  throw new Error('Set AGENT_WORKSPACE_URL and AGENT_WORKSPACE_API_KEY');
}
const aw = createClient({
  baseUrl,
  auth: { kind: 'api-key', apiKey },
});

async function main(): Promise<void> {
  const token = process.env.GITHUB_TOKEN;
  if (token === undefined) throw new Error('Set GITHUB_TOKEN');
  const secret = await aw.secrets.create({
    name: 'GITHUB_TOKEN',
    value: token,
  });
  console.log(`stored ${secret.name} (${secret.id}), sealed with ${secret.algorithm}`);

  const secrets = await aw.secrets.list();
  console.log(secrets.map((s) => s.name));

  try {
    await aw.secrets.replace(secret.id, 'a-fresh-token-value');
  } catch (error) {
    if (error instanceof ApiProblemError) console.error(error.code);
    else throw error;
  }
}

main();
```

## `list`

Every secret of the caller's workspace, metadata only — the array never carries a `value` field,
for any secret, under any circumstance.

**Route:** `GET /api/secrets`

```ts title="illustrative" claim="illustrative"
const secrets = await aw.secrets.list();
```

No secrets-specific problem codes; see [Errors](/guides/errors) and
`503 secrets_runtime_not_configured` below.

<CodeGroup>

```sh title="aw (illustrative)" claim="illustrative"
aw secrets list
```

</CodeGroup>

See [`secrets.list`](/reference/sdk/secrets#list).

## `create`

Store a new secret. `name` must match `SECRET_NAME_PATTERN` and be unique in the workspace;
`value` must be 1 to `SECRET_VALUE_MAX_LENGTH` (65 536) code units. The value is sent once and
never returned — the response is metadata only.

**Route:** `POST /api/secrets`

```ts title="illustrative" claim="illustrative"
const secret = await aw.secrets.create({ name: 'ANTHROPIC_API_KEY', value: 'sk-ant-...' });
```

| Code                             | Status | Meaning                                                                                                         |
| -------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------- |
| `invalid_body`                   | 400    | `name` outside `SECRET_NAME_PATTERN`, `value` empty or too long, or an unknown key. `details` names each field. |
| `secret_name_conflict`           | 409    | The workspace already has a secret with this name.                                                              |
| `secrets_runtime_not_configured` | 503    | This deployment has no secrets backend configured.                                                              |

Source: verified against `apps/web/server/secrets/handlers.ts`.

<CodeGroup>

```sh title="aw (illustrative)" claim="illustrative"
printf '%s' "$ANTHROPIC_API_KEY" | aw secrets create --name ANTHROPIC_API_KEY --value-stdin
```

</CodeGroup>

`aw secrets create` also accepts `--file <json>` in place of `--name`/`--value-stdin`. See
[`secrets.create`](/reference/sdk/secrets#create) and
[`CreateSecretInput`](/reference/contracts/secrets#createsecretinput).

## `replace`

Rotate a secret's value in place — its `name` and `id` stay. The name is immutable through this
route; a body that tries to send one is refused.

**Route:** `PUT /api/secrets/:id`

```ts title="illustrative" claim="illustrative"
const rotated = await aw.secrets.replace(secretId, 'a-fresh-value');
```

| Code                             | Status | Meaning                                                |
| -------------------------------- | ------ | ------------------------------------------------------ |
| `invalid_secret_id`              | 400    | The `:id` in the path is not a UUID.                   |
| `invalid_body`                   | 400    | `value` empty or too long, or the body carries `name`. |
| `secret_not_found`               | 404    | No secret with that id in this workspace.              |
| `secrets_runtime_not_configured` | 503    | This deployment has no secrets backend configured.     |

<CodeGroup>
```sh title="aw (illustrative)" claim="illustrative"
printf '%s' "$NEW_VALUE" | aw secrets replace <id> --value-stdin
```
</CodeGroup>

See [`secrets.replace`](/reference/sdk/secrets#replace) and
[`ReplaceSecretInput`](/reference/contracts/secrets#replacesecretinput).

## `remove`

Delete a secret nothing references. A secret a connector authenticates with, or one a model
connection owns, is refused rather than deleted: the `409 secret_in_use` problem names every
referrer in `details` as `connector:<id>` or `model-connection:<id>`, and nothing changes. Remove
or re-point those referrers, then retry. Only an Owner may delete a secret; every other role is
`403`, whether or not the id exists.

**Route:** `DELETE /api/secrets/:id` — `204` on success.

```ts title="illustrative" claim="illustrative"
import { parseInUseReferrers } from '@indx-workspace/contracts';
import { ApiProblemError } from '@indx-workspace/sdk';

try {
  await aw.secrets.remove(secretId);
} catch (error) {
  if (error instanceof ApiProblemError && error.code === 'secret_in_use') {
    console.log(parseInUseReferrers(error.details)); // [{ kind: 'connector', id: '…' }]
  }
}
```

| Code                | Status | Meaning                                                                            |
| ------------------- | ------ | ---------------------------------------------------------------------------------- |
| `invalid_secret_id` | 400    | The `:id` in the path is not a UUID.                                               |
| `forbidden`         | 403    | The caller is not an Owner.                                                        |
| `secret_not_found`  | 404    | No secret with that id in this workspace (another workspace's id included).        |
| `secret_in_use`     | 409    | A connector or model connection still references the secret; `details` names each. |

<CodeGroup>
```sh title="aw (illustrative)" claim="illustrative"
aw secrets remove <name|id>
```
</CodeGroup>

See [`secrets.remove`](/reference/sdk/secrets#remove).

## How a secret reaches an agent's runtime

This is a repository-level design decision, not an SDK method — described here because it is the
reason secrets exist at all. The platform specification states it directly: a secret's value is
never embedded in an agent definition, a skill file, an MCP file, or a database-visible JSON blob.
Instead, "the runtime receives only the secrets required by that particular agent" (§23), passed
as `env` to the Claude Agent SDK's own sandbox options at run time (§14.7) — never the full host
environment. Which secrets a given agent needs, and how that set is decided, is not part of the
Agent Workspace SDK's contracts today; it is a platform-level design.
