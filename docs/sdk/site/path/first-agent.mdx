**Where you are:** the start of the path. Next: [Chapter 2: Build your agent](/path/build).

## What you will have at the end

A project made from the `support` theme, running on your laptop: the agent `assistant` with its
`refund-policy` skill, answering in the browser on the `try` page and in the terminal through
`aw chat`, and a web console where you see the agent, its skill and its model. Every file that
defines it is in your project directory, ready to commit. On a clean machine with a fast network,
the first answer comes about a minute after the first command.

    `npm create`, `npm run dev`, then chat in the browser and the terminal, change the surface and

  <Step title="Talk to it from the terminal">
    Run `npx aw chat` for a conversation, or `-p` for one answer in a script. You learn which
    version answers and the three SDK calls behind a chat turn. [aw chat](/cli/chat)
  </Step>
</Steps>

## What is not there yet

- The local runtime is for development only: runs use the in-process `local` driver, which has no
  isolation and runs commands as you. To run the agent in a Docker container instead, opt in with
  `npx aw dev --sandbox docker`; it needs Docker running. The container's network is `open` and
  goes through no egress proxy locally, so it limits file and process access, not what the agent
  can reach on the network. For now it needs a runtime image built from the Agent Workspace
  repository and runs only agents with `unrestrictedNetwork` (issue #786). See
  [the Docker sandbox](/getting-started/troubleshooting#the-docker-sandbox-refuses-to-start-or-the-run-fails).
