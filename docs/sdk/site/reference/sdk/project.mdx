## appKitSatisfies

Whether the installed app-kit `version` lies in a blueprint's `appKit` `range` (ADR-0166 D5).
The range is an exact version, `^x.y.z` or `~x.y.z`, with npm's meaning: `^1.2.3` is
`>=1.2.3 <2.0.0`, `^0.9.0` is `>=0.9.0 <0.10.0`, `^0.0.3` is `0.0.3` only, and `~1.2.3` is
`>=1.2.3 <1.3.0`. A pre-release matches only exactly. Anything else, a malformed range or
version included, does not match.

```ts
appKitSatisfies(range: string, version: string): boolean
```

## askSetupQuestions

The one setup question loop `create` and `aw init` ask through (C20; issue #543). It is
isomorphic: `prompt` shows one question and resolves with the typed line, and `say` shows one
line of output; the caller owns the terminal.

Asks each of `SETUP_QUESTIONS` that applies, in order; a question whose `when` the answers so
far do not meet is skipped. An empty line takes the recommended answer — the chosen theme's,
then the question's own; a multi answer is typed comma-separated. An answer
`SetupAnswersSchema` refuses together with the earlier answers is passed to `say` with its
grammar, and the same question is asked again. A question `preset` already answers (from a flag)
is not asked.

With `choose` (a terminal's arrow-key menu) every choice and multi question is a menu with the
recommendation preselected, and a theme shows its one-line summary; without it the typed path
above is used. Text questions are always typed.

```ts
async askSetupQuestions(prompt: (question: string) => Promise<string>, say: (line: string) => void, preset?: SetupAnswers, choose?: Choose): Promise<CompleteSetupAnswers>
```

## planProjectResources

What `aw dev` creates, updates, refuses and reports to bring the workspace in step with the
project file and its agents' tools (C10, C11, C15, SD16). Pure and synchronous: it reads nothing
but its input, which is already schema-parsed, so it does not validate it again.

- **No secret value.** An action names its secret; the caller reads the value, sends it, and
  records its fingerprint. An unset secret is a notice, and its resource is skipped.
- **Rotation.** A credential is sent again when the server has none or when its fingerprint
  differs from the one recorded at the last send; no recorded one counts as different.
- **Never deletes.** A resource the project does not declare is left alone.
- **Models.** With `models`, each is created or its config and credential updated; a provider
  cannot change, so a mismatch is a refusal. Without, a missing `default` is created from
  `ANTHROPIC_API_KEY` (C6), and an existing one follows that key and `ANTHROPIC_BASE_URL` (#732).
- **Connectors and tools** share one namespace (SD1): a name of another kind or transport is a
  refusal. A tool is updated with its whole create body, credential included.

- **Skills.** Each `skills/<name>/` folder is a `skills` entry: created, updated when its content
  hash differs, else unchanged. A workspace skill with no folder is left alone.

Actions come in the order declared: models, connectors, then tools.

```ts
planProjectResources(input: PlanProjectResourcesInput): ProjectResourcePlan
```

## renderProjectFiles

Renders the files a project's setup answers are written into, in `SETUP_FILE_PATHS` order:
`agent-workspace.yaml`, `agents/<agentName>.ts`, `surfaces/main.ts`, then one `tools/<name>.ts`
per internal tool, sorted by name (issue #543, SD9, SD12), then the theme's starter files
(`starters/<theme>/`: `automation` adds tools, a fake API, a README and its eval file; `support`
and `copilot` a README and eval file, `copilot` also a Vite page in `web/`; an internal tool that
would write one of a starter's paths is refused). `aw init` refuses a directory where any of
them exists, as it does for every rendered path, except an existing `README.md` or `AGENTS.md`,
which it keeps. `AGENTS.md` tells a coding agent how to run the project without a terminal.

- `agent-workspace.yaml` is a v2 `Project` with one `local` environment; it names a runtime only
  when the sandbox answer is not `auto`, and no port or storage (`aw dev` provides both). A model
  provider other than `anthropic` adds `models.default`: its credential is a secret reference,
  and each required setting no question asks for is a `your-` placeholder the header names.
- The agent carries the theme's instructions and any permissions the answers switch on, and
  imports and lists each tool; the surface carries the theme's greeting and suggested prompts.
  Theme `blank` renders the slice-1 files byte for byte.
- A platform answer other than `none` adds a `platforms:` block to `agent-workspace.yaml` (in
  `PLATFORM_IDS` order) and the `aw platforms` commands to `README.md` and `AGENTS.md`; `none`
  changes no file.
- A features answer that is not every feature adds a `features:` list (in `FEATURE_IDS` order);
  an absent answer or every feature writes no key, which means all installed (ADR-0160 D5).
- An OpenAPI tool is named after its document's file name up to the first `.`, reads its token
  from `<NAME>_TOKEN` and allows only `GET` and `HEAD`; the PostgreSQL tool reads its URL from
  `POSTGRES_URL` and names one placeholder table.
- Every definition is passed through its `define*` call before it is printed, so a file this
  writes always loads.

The result is frozen. `project.name` is the project's name key; `projectNameFor` derives one from
a directory name.

```ts
renderProjectFiles(answers: CompleteSetupAnswers, project: { readonly name: string; readonly version?: string }): readonly ProjectFile[]
```
