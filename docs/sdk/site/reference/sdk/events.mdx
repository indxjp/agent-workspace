## assistantResponseFromAgentEvent

Read the assistant's visible answer from one neutral event, or `null` when it carries none.

The boundary is deliberately strict, and it is the same rule the browser's run view has always
applied: only an assistant message with an engine message id and at least one non-blank text
block becomes a chat turn. Reasoning blocks, tool calls, usage and results cannot leak into the
conversation — the answer is product content, while the rest is telemetry and belongs in
Technical details.

```ts
assistantResponseFromAgentEvent(event: AgentEvent): AssistantResponse | null
```

## parseSseFrame

Parse one frame's raw text (already split on the blank-line boundary) into `{ event, id, at?, data }`,
or `null` for a frame with no `event:` field.

The platform never sends an unnamed frame, so `null` here means text this parser could not read
as this wire format at all, and the caller drops it rather than guessing a name for it.

## RunEventFrame

One frame of a run's event stream, classified.

  * `run-status`   — the platform's durable lifecycle event; `id` is a resume cursor.
  * `runtime`      — a durable event the runtime produced; `id` is a resume cursor. Since ENG-03
                     (#302) `name` is one of `@indx-workspace/contracts`' `AGENT_FRAME_NAMES` and
                     `data` is that frame — one engine-neutral vocabulary, normalised by the
                     engine's adapter in the runner. `toAgentEvent` (`./agent-event.ts`) is the
                     parser that validates it; nothing else should read `data`.
  * `run-failed`   — this connection could not deliver a successful run (see the contract).
  * `stream-reset` — what follows is not contiguous with what the client already has.
  * `done`         — the stream is over. It says nothing about whether the run succeeded.

`at` on the two durable variants is when the control plane recorded the event, not when the
engine produced it. It is absent when the server sent none (a server before the `at:` field).

`data` is left `unknown` here and validated by the parser rather than by this classifier, so that
the frame's *kind* and the frame's *payload* fail separately: a payload that does not satisfy its
schema must not make the stream unreadable for a consumer that only wanted the resume cursor.

- `{ readonly kind: "run-status"; readonly id: string | null; readonly at?: string; readonly data: RunStatusEventData; }`
- `{ readonly kind: "runtime"; readonly id: string | null; readonly at?: string; readonly name: string; readonly data: unknown; }`
- `{ readonly kind: "run-failed"; readonly data: RunFailedFrameData; }`
- `{ readonly kind: "stream-reset"; readonly data: StreamResetFrameData; }`
- `{ readonly kind: "done"; }`

## SseFrame

One parsed SSE frame: the `event:` name, its `id:` when the server sent one, and its payload.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `event` | `string` | Yes |  |
| `id` | `null \| string` | Yes | `null` for every control frame — the platform never gives one an `id:`, because none of them may move a client's resume cursor. |
| `at` | `undefined \| string` | No | The `at:` field: when the control plane recorded a durable event, as the server wrote it. Absent on control frames and on servers that predate the field; `classifyRunEventFrame` validates it. |
| `data` | `unknown` | Yes | The `data:` field(s), joined and JSON-parsed. Kept as the raw joined string when it does not parse — the platform only promises JSON for the frames it writes itself, and a frame this parser cannot make sense of is still worth surfacing verbatim rather than dropping silently. |

## toAgentEvent

The neutral event one frame carries, or `null` for the platform's own frames.

`run-status`, `run-failed`, `stream-reset` and `done` are already typed on `RunEventFrame`
and are not agent events: they are the *platform* speaking about the run and the stream, not the
engine speaking about the turn. Conflating the two is how a failed run gets rendered as a
finished one, so they stay apart.

```ts
toAgentEvent(frame: RunEventFrame): AgentEvent | null
```
