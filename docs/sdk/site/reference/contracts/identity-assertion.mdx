## ConnectorIdentitySchema

An opt-in `identity: { secret: NAME }` on a connector (project file and connector resource): a
reference to the signing secret by name, never the key itself, and never a storage connection's
credential (a `STORAGE_CONNECTION_` name): that credential is bound to the connection's URL and
is never a signing key.

| --- | --- | --- | --- |
| `secret` | `string` | Yes |  |

## signIdentity

Signs `payload` into the header value `base64url(JSON payload).base64url(HMAC-SHA256)`. The MAC
covers the encoded payload text. Throws on a payload the schema refuses or an empty key: both are
a programming error on the platform side, not input.

```ts
async signIdentity(payload: IdentityAssertionPayload, key: string): Promise<string>
```

## verifyIdentity

Checks an `x-aw-identity` header value against the connector's secret(s) (a list while the secret
rotates). In order: the header's shape, the signature, the payload's exact six keys, `exp` (with
`IDENTITY_ASSERTION_SKEW_SECONDS` of skew), then `aud` and `workspace` against `expected`.
It never throws on bad input, and a refusal carries a code only.

```ts
async verifyIdentity(header: string, key: string | readonly string[], now: Date, expected: IdentityExpectation): Promise<IdentityVerification>
```
