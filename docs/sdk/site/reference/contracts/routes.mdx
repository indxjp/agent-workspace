## API_ROUTE_EXCLUSIONS

Declared routes that are not part of the programmatic surface, and why. Two kinds (ADR-0080):

- browser journeys — spec 04 §1 puts first-run setup, OIDC sign-in and the public share pages
  permanently out of scope;
- private runner routes — the transcript writes and the ENG-06 engine-state routes, which only
  `apps/runner` calls, with the signed per-run token rather than a workspace credential
  (`apps/web/server/sessions/state-api.ts`; 04 §5.11: runtime-only, not exposed by the SDK).

The platform's own callers sit beside them: the cron jobs (`CRON_SECRET` bearer, ADR-0120) and
the readiness probe a kubelet calls with no credential (issue #1562). The `aw-control` MCP door a
running agent reaches through the gateway (issue #1846) accepts only a run token, as a `run-caller`.

## API_SCHEMAS

Every contract schema an entry below may name, keyed by its exported name.

## ApiBody

What travels in a request or response body.

- `json` — `application/json`, parsed with the named schema; more than one name lists the
  alternatives a route answers on the same status (a client tells them apart by shape).
- `json-undescribed` — `application/json` the contracts do not yet describe (see the header).
- `binary` — opaque bytes (`application/octet-stream`, or the stored file's own type).
- `event-stream` — `text/event-stream`; `frames` names the schemas of each frame's `data:`.
- `none` — no body (`204`, or a request that sends nothing).

- `{ readonly kind: "json"; readonly schemas: readonly [ApiSchemaName, ...ApiSchemaName[]]; }`
- `{ readonly kind: "json-undescribed"; }`
- `{ readonly kind: "binary"; }`
- `{ readonly kind: "event-stream"; readonly frames: readonly ApiSchemaName[]; }`
- `{ readonly kind: "none"; }`

## ApiRoute

One public route and the contracts it is parsed with.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `method` | `"GET" \| "POST" \| "PUT" \| "PATCH" \| "DELETE"` | Yes |  |
| `path` | `string` | Yes | The path in the specification's own notation: `:id`, not `[id]` or `{id}`. |
| `operationId` | `string` | Yes | Stable and unique: the SDK operation name where one exists (`agents.list`). |
| `tag` | `string` | Yes | The SDK resource family the route belongs to; the OpenAPI tag. |
| `summary` | `string` | Yes |  |
| `request` | `undefined \| { readonly kind: "json"; readonly schemas: readonly [ApiSchemaName, ...ApiSchemaName[]]; } \| { readonly kind: "json-undescribed"; } \| { readonly kind: "binary"; } \| { readonly kind: "event-stream"; readonly frames: readonly ApiSchemaName[]; } \| { readonly kind: "none"; }` | No | Absent when the request carries no body. |
| `success` | `readonly ApiSuccess[]` | Yes |  |
| `deprecated` | `undefined \| true` | No | Kept for one release and replaced by another route (04 §4). |
| `security` | `undefined \| "none" \| "session-cookie" \| "invitation-identity" \| "user-token" \| "endpoint-credential"` | No | How the caller proves who it is, when that is not the default — a workspace API key, a browser token or the control plane's session cookie. Mirrors the public and identity-only routes of `apps/web/server/rbac/authorisation-matrix.test.ts`: - `none` — no identity proof at all; - `session-cookie` — only the control plane's own browser session (the route is exempt from the proxy's session gate and checks the cookie itself); - `invitation-identity` — the invitation-identity cookie, not a workspace credential; - `user-token` — only the `awu_live_` token `aw login` holds, which the route acts on itself (revoke it, move it to another workspace; ADR-0083); - `endpoint-credential` — only an endpoint-scoped key, a workspace API key or (T1c) an OAuth access token, never a browser session: the published-agent endpoint (ADR-0135) is exempt from the proxy's session gate and authenticates the bearer itself. |
