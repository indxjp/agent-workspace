<Info>

**Chapter 1 · Run your first agent — step 3 of 4** · [the chapter map](/path/first-agent)

- **You will:** sign in to the web console and look at each screen once.
- **You will learn:** where the agent, its skill, its model and its runs are, and which later chapter uses each screen.
- **You need:** `npm run dev` running from the [Quickstart](/getting-started/quickstart). Five minutes.

</Info>

The web console is the same project seen by an admin: what you wrote as files under `agents/`,
`surfaces/` and `skills/` shows up here, next to what the workspace adds (models, runtimes, keys,
users). You do not have to use it to build an agent; it is where you look, and where someone who
does not edit files works.

## Sign in

Open the `console` URL from the ready screen, [http://127.0.0.1:3000](http://127.0.0.1:3000).

<Frame caption="The sign-in page of the local console.">
  <img src="/images/console/01-sign-in.png" alt="The Agent Workspace sign-in page with Email and Password fields, under the banner Runtime driver in force: local" />
</Frame>

- **Email:** `admin@localhost.test`, the workspace owner. The ready screen's `console` row names it.
- **Password:** printed once, on the first line of the first `npm run dev`:
  `Sign in at http://127.0.0.1:3000 as admin@localhost.test with password … (shown once; …)`. It
  is also kept in the project, in `.agent-workspace/local-secrets.json` under the key
  `BOOTSTRAP_ADMIN_PASSWORD`. That file is in `.gitignore`; never commit it.

From the next release the password is no longer printed, and the file is
`.agent-workspace/secrets/local-secrets.json`.

Every screen shows the banner `Runtime driver in force: local — No tenant isolation: commands run
as the host user`. That is the local runtime telling the truth: runs execute on your machine as
you. It is for development only.

## New chat

The home screen. Pick an agent, a model, files and connectors, and start a conversation, as a
user of the workspace would. The line under the box says which model the agent runs on:
`Runs as assistant on claude-sonnet-4-5 or its newest dated release (default, the deployment
default)`.

<Frame caption="New chat: the agent assistant, its model, and the local runtime badge.">
  <img src="/images/console/02-home.png" alt="The New chat screen with the prompt box, the Model, Agent, Files and Connectors pickers, and the line Runs as assistant on claude-sonnet-4-5" />
</Frame>

The words `Everything runs in a sandbox` and `Standard Sandbox · read-only` on this screen describe
a deployment. On the local runtime the banner above is what holds: no isolation.

**Used in:** [Chapter 4: Put it in your product](/path/embed), for the users who chat here.

permissions, the same values as `agents/assistant.ts`. **Versions** lists every version your
saves created, and **Platforms** what it is published to elsewhere.

## Runs

Every run the agent made, with its steps, tool calls, tokens and cost.

<Warning>

In 0.6.9 the **Runs** screen fails to show runs: it says
`The server's answer did not look like a run list`. The fix ships in the next release. Until then,
the terminal shows the same run.

</Warning>

List the runs with `npx aw runs list`, then trace one with `npx aw runs trace <run-id>`. This is
the run of the Quickstart's `aw chat` question:

```text title="Output"
run ea97dd4d-a5eb-4874-98ff-6cd2f21480be completed 8543ms tokens=60276 cost=0.000000 USD (accounting unavailable)
├─ step 1 +3.3s: I'll check the refund policy for you.
│  └─ Skill (other) completed +4.3s 12ms
│        input: {"args":"mug bought 20 days ago","skill":"refund-policy"}
│        output: Launching skill: refund-policy
├─ step 2 +7.2s: Yes, you can return the mug! Our refund policy allows returns within 30 days of purchase, and you're at 20 days, so you're well within the timeframe. To process your return, I'll need your order numb…
└─ result stop=end_turn +8.2s turns=3 engine-tokens=926/370 engine-cost=$0.1284 (estimate)
```

<Frame caption="aw runs trace: the run's two steps, the refund-policy skill call, and the engine's cost estimate.">
  <img src="/images/quickstart/07-run-trace.png" alt="A terminal running npx aw runs trace: the run line, step 1 with the Skill tool call to refund-policy, step 2 with the answer, and the result line with the engine cost estimate" />

The agent loaded its `refund-policy` skill in step 1 and answered in step 2. Locally the run's own

The model providers behind the workspace's gateway. `default` is the Anthropic connection
`aw dev` made from your key; agents select a model and never see the credential.

## Runtimes

Where agent sessions run. On the local runtime, **This machine** is selected and marked
`No isolation`; Docker, Kubernetes and the managed sandboxes become selectable once they are
configured and pass a test.

<Frame caption="Runtimes: This machine selected, the other drivers not configured.">
  <img src="/images/console/10-runtimes.png" alt="The Runtimes screen with This machine selected and marked No isolation, and Sandboxed process, Docker, Kubernetes and managed sandboxes listed as Unverified" />
</Frame>

**Used in:** [Chapter 2](/building/models-and-runtimes) and
[Chapter 5: Ship it to your servers](/path/ship).

## API Keys

Keys for code and scripts that call the workspace. The key listed, `aw dev local runtime …`, is
the one `aw` uses inside the project; `npx aw me` shows the same label. A new key's secret is
shown exactly once.

[Authentication](/getting-started/authentication).
