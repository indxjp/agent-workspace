rest have sensible defaults. For the full type signature, see [Client](/reference/sdk/client).

<Accordion title="The ClientOptions and RequestOptions types">

```ts title="illustrative" claim="illustrative"
interface ClientOptions {
  readonly baseUrl: string | URL;
  readonly auth: ClientAuth;
  readonly fetch?: typeof fetch;
  readonly headers?: Readonly<Record<string, string>>;
  readonly timeoutMs?: number;
}

interface RequestOptions {
  readonly signal?: AbortSignal;
}
```

</Accordion>

## Point the client at your control plane

`baseUrl` is the control plane's origin, optionally with a path prefix; it accepts a `string` or
a `URL`. `auth` is required too, with no default — see
[Authentication](/getting-started/authentication) for which kind to use.

```ts title="illustrative" claim="illustrative"
createClient({ baseUrl: 'https://agents.example.com', auth /* … */ });
createClient({ baseUrl: 'https://example.com/aw', auth /* … */ }); // path prefix
```

The prefix is kept: `https://example.com/aw` plus `/api/agents` resolves to
`https://example.com/aw/api/agents`, and a trailing slash on `baseUrl` is stripped first.

<Accordion title="How request paths are joined (resolveApiUrl)">

```ts title="illustrative" claim="illustrative"
export function resolveApiUrl(baseUrl: string | URL, path: string, query?: URLSearchParams): URL {
  const base = new URL(String(baseUrl));
  const prefix = base.pathname.replace(/\/+$/u, ''); // trailing slashes dropped
  const url = new URL(`${prefix}${path}`, base.origin);
  if (query !== undefined) url.search = query.toString();
  return url;
}
```

</Accordion>

## Add a header to every request

`headers` adds extra headers to every request — a trace id, a `User-Agent`, anything your
infrastructure wants attached. They are applied after the SDK's own `accept`, `content-type` and
(for `api-key` auth) `authorization` headers, so a header here can override the SDK's default
`accept` or `content-type` but not silently disappear.

<Warning>
  Never put a credential in `headers`. Authentication is `auth`'s job; `headers` exists for
  everything else. The client already refuses to let you pass an `Authorization` value through
  `auth` for anything but the defined `ClientAuth` kinds, and there is no supported way to smuggle a
  second credential through here — do not try.
</Warning>

## Give up when the server does not answer

`timeoutMs` aborts a request that has produced **no response headers** within that many
milliseconds. It covers headers only: once `fetch` resolves, a streamed body (`runs.events`,
`runs.follow`) may stay open far longer. There is no separate "whole request" or "whole stream"
timeout in the SDK.

A timeout surfaces as a `TransportError` with `aborted: true` (its `cause` is a `DOMException`
named `TimeoutError`) — indistinguishable, by design, from an ordinary dropped connection.
`runs.follow` treats it like any other dropped connection and reconnects; only the caller's own
`{ signal }` ends a `follow` call for good. See [Timeouts and
cancellation](/guides/timeouts-and-cancellation) for the full mechanics.

## Cancel one call or stream

Every SDK method takes a trailing options argument with one field, `signal`:

```ts title="illustrative" claim="illustrative"
const controller = new AbortController();
const promise = aw.runs.get(runId, { signal: controller.signal });
controller.abort();
```

Aborting ends the call — including a stream started with `events` or `follow` — with a
`TransportError` whose `aborted` is `true`. This is the only cancellation mechanism the SDK has;
there is no method-level timeout separate from the client-wide `timeoutMs`.

## Bring your own fetch

`fetch` defaults to the global `fetch`, bound to `globalThis`. Pass your own for a test double, a
runtime without a global `fetch`, or a `fetch` that wraps the real one (retries, logging, a
proxy). Anything conforming to the standard `fetch` signature works, including one that returns a
`ReadableStream` body for `runs.events`/`runs.follow` to read. See [Testing](/guides/testing) for
injecting a `fetch` in your own tests.

The SDK also ships a ready-made fetch double as `@indx-workspace/sdk/testing`; see
[Testing](/guides/testing).

## Environment variables

`createClient` reads **no environment variables**. Every option is passed explicitly; how the
value reaches your code — `process.env`, a secrets manager, a config file — is up to you.

`AGENT_WORKSPACE_URL` and `AGENT_WORKSPACE_API_KEY` are the names the `aw` CLI reads, and this
documentation uses the same two names by convention so an example works the same way as a script
or through `aw`. The snippet that reads them is on
[Authentication](/getting-started/authentication#api-key-—-a-backend-ci-or-the-cli).

See [Configuration](/cli/configuration) for the CLI's full precedence order (flags, then these two
variables, then the project file `agent-workspace.yaml`, then the `default` profile). When the URL
comes from the project file, `aw` never sends `AGENT_WORKSPACE_API_KEY` or a profile's key to it:
it uses a key piped with `--api-key-stdin`, else the local key `aw dev` stored for that URL, else
the token `aw login` stored for it.

## Tell the server where files live

Your code never names a bucket: `aw.files`, `aw.skills` and the session transcripts are stored
wherever the server keeps them. The operator sets that once, with one server environment variable,
`AW_STORAGE_URL`. The control plane reads it; `createClient` does not. The URL never holds a key or
a password: those come from the environment, or from the cloud's workload identity.

| Scheme      | Store                                                                    | Example                                 | Query parameters                                                                                                               |
| ----------- | ------------------------------------------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `s3://`     | Amazon S3, or an S3-compatible server such as Cloudflare R2 or SeaweedFS | `s3://acme-files/prod?region=eu-west-1` | `endpoint`, `publicEndpoint` (the origin a browser uses for signed links), `region`, `pathStyle` (`true` or `false`)           |
| `gcs://`    | Google Cloud Storage                                                     | `gcs://acme-files/prod?project=acme-ai` | `project`                                                                                                                      |
| `azblob://` | Azure Blob Storage: the storage account, then the container              | `azblob://acmefiles/objects/prod`       | `endpoint`, the account's blob endpoint in a sovereign cloud (for example `https://acmefiles.blob.core.usgovcloudapi.net`)      |
| `file://`   | a folder on the server's own disk, for one machine                       | `file:///var/lib/agent-workspace`       | none                                                                                                                           |

The path after the bucket or container is a prefix, and every object goes under it. The server
refuses a URL with a user name or password in it, an unknown query parameter, a `#fragment`, or an
empty, `.` or `..` path segment. Its error message never repeats the value.

The server still starts when `AW_STORAGE_URL` is unset or invalid. It logs why, and the files,
skills and session-state routes answer `503` (`files_runtime_not_configured`,
`skills_runtime_not_configured`) until the URL is fixed and the server restarts.
`agent-workspace doctor` fails its storage check for an invalid URL and warns when none is set.
A malformed value of a setting beside it, such as `AW_STORAGE_SIGNED_UPLOAD_MAX_BYTES`,
`AW_STORAGE_CREATE_BUCKET` or `AW_STORAGE_CLEANUP`, does stop start-up, with a message that names
the variable and not its value.

Which stores can sign upload and download links, the size limits, and how to move from the old
storage variables are on [The data plane](/concepts/data-plane#one-storage-url).
