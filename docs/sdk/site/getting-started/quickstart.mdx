<Info>

**Chapter 1 · Run your first agent — step 2 of 4** · [the chapter map](/path/first-agent)

- **You will:** create a project with `npm create`, start it with `npm run dev`, and talk to your agent.
- **You will learn:** what the generator writes, what the ready screen tells you, and how a saved file reaches the running agent.
- **You need:** Node 24 or newer and an Anthropic API key ([Before you begin](/getting-started/installation#before-you-begin)). About one minute to a running agent, ten for the whole page.

</Info>

## What you will have

A customer-support agent running on your laptop, answering in the browser:

<Frame caption="The try page of the new project: the agent checks its refund-policy skill and answers.">
  <img src="/images/quickstart/03-try-chat.png" alt="The try page: a customer asks whether they can return a mug bought 20 days ago; the agent says it will check the refund policy, then answers that returns are accepted within 30 days and asks for the order number" />
</Frame>

It is one Node process with an embedded PostgreSQL. Docker is not needed. Every file that defines
the agent is in your project directory, ready to commit.

## Before you begin

Check Node 24 and get an Anthropic API key: [Installation](/getting-started/installation#before-you-begin).
On Windows, use a terminal that is not elevated.

## Your first agent

<Steps>
  <Step title="Set your key">

Set the key in the shell you will run the project from. `aw dev` reads it from the environment and
never writes it to the project.

<Tabs>
  <Tab title="macOS, Linux, WSL, Git Bash">

```bash title="Replace the placeholder with your key (illustrative)" claim="illustrative"
export ANTHROPIC_API_KEY=sk-ant-...
```

  </Tab>
  <Tab title="PowerShell">

```powershell title="Replace the placeholder with your key (illustrative)" claim="illustrative"
$env:ANTHROPIC_API_KEY = 'sk-ant-...'
```

  </Tab>
  <Tab title="cmd.exe">

```bat title="Replace the placeholder with your key (illustrative)" claim="illustrative"
set ANTHROPIC_API_KEY=sk-ant-...
```

  </Tab>
</Tabs>

Forgot it? `aw dev` offers to open the provider's console and take the key there
([key missing](/getting-started/troubleshooting#aw-dev-says-the-model-key-is-missing)).

  </Step>
  <Step title="Create the project">

```sh claim="run"
npm create @indx-workspace@latest my-agent -- --yes
cd my-agent
npm run dev
```

The last line, `npm run dev`, starts the agent; the next step shows what it prints. The first
command writes the project and installs its dependencies; `--yes` takes every
recommended answer, so nothing is asked. The generator's flags go after npm's `--`. You see the
files it wrote (npm's own warning and update notices are left out):

```text title="Output"
> npx
> 'create-indx-workspace' my-agent --yes

Created /home/node/my-agent
  package.json
  pnpm-workspace.yaml
  .gitignore
  agent-workspace.yaml
  agents/assistant.ts
  surfaces/main.ts
  README.md
  evals/assistant.yaml
  AGENTS.md
  skills/refund-policy/SKILL.md
```

It says `aw dev reads ANTHROPIC_API_KEY from its environment; no key is written to a file.`, then
installs the dependencies and ends with the next steps:

```text title="Output"
added 181 packages, and audited 182 packages in 31s

47 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities
Next steps:
  cd my-agent
  npm run dev
```

When the key is not set in that shell, `Next steps` also prints the line that sets it for your
shell. The project is plain files: the agent in `agents/assistant.ts`, its chat page in
`surfaces/main.ts`, a `refund-policy` skill, three evaluation cases, and an `AGENTS.md` for coding
agents.

<Frame caption="npm create in a terminal: about 35 seconds on a clean machine.">
  <img src="/images/quickstart/01-create.png" alt="A terminal running npm create @indx-workspace@latest my-agent -- --yes and listing the ten files it wrote" />
</Frame>

Without `--yes`, on a terminal, `npm create @indx-workspace@latest` asks its setup questions as
menus instead; see [What npm create asks](/cli/dev#what-npm-create-asks-and-writes).

  </Step>

`npm run dev` runs `aw dev`: the local runtime, one Node process with an embedded PostgreSQL.
It prints one screen when everything is up, about five seconds later:

```text title="Output"

model connection: default (anthropic)

  try       http://127.0.0.1:3000/p/s/main/try

  chat      npx aw chat

    runtime   ready in 3.6 s   logs: .aw/logs/runtime.log
    model     default · workspace default model · key checked
    signed in as admin@localhost.test (workspace default)
    agent     assistant  (agents/assistant.ts)
    surface   main

  evals     3 cases · npx aw eval

```

<Frame caption="The same screen in a terminal, where each ready row also gets a tick.">
  <img src="/images/quickstart/02-ready-screen.png" alt="The aw dev ready screen: the try URL, the console URL with the sign-in email and where the password is, and the chat command, then ticks for runtime, model, sign-in, agent and surface" />
</Frame>

The first line shows the console password once (masked here); you need it for the
[console tour](/getting-started/console-tour). Leave this terminal running: it watches your files.
On a terminal, `aw dev` then asks `Open the chat in your browser? (Y/n)`. Every row is explained in
[aw dev in depth](/cli/dev#the-ready-screen-line-by-line).

**Check:** the `model` row ends in `key checked`, and the last line is `synced: … "assistant" created at version 1`.

The ready screen says `3000 was busy`, or nothing starts? See
[A port is busy](/getting-started/troubleshooting#a-port-is-busy). On Windows, PostgreSQL refusing
to start means an [elevated shell](/getting-started/troubleshooting#windows-postgresql-refuses-to-start-in-an-elevated-shell).

  </Step>
  <Step title="Chat in the browser">

Open the `try` URL, [http://127.0.0.1:3000/p/s/main/try](http://127.0.0.1:3000/p/s/main/try), and ask
`Can I return a mug I bought 20 days ago?`. The agent says it will check the refund policy, reads
its `refund-policy` skill, and answers.

**Check:** the answer says returns are accepted within 30 days, and the run shows `Completed`
(the picture at the top of this page).

  </Step>
  <Step title="Chat in the terminal">

Open a second terminal in `my-agent` (it needs no key: the running `aw dev` has it) and send one
prompt with `npx aw chat -p "Can I return a mug I bought 20 days ago?"`:

```text title="Output"
I'll check the refund policy for you.
Yes, you can return the mug! Our refund policy allows returns within 30 days of purchase, and you're at 20 days, so you're well within the timeframe.

To process your return, I'll need your order number. Could you provide that?
```

<Frame caption="aw chat -p prints the answer on stdout, about nine seconds here.">
  <img src="/images/quickstart/04-aw-chat.png" alt="A terminal running npx aw chat -p with the mug question and the agent's refund answer" />
</Frame>

Without `-p`, `npx aw chat` opens a conversation that streams each answer. See [aw chat](/cli/chat).

**Check:** the answer is printed and the command exits.

  </Step>
  <Step title="Change it and watch it update">

Open `surfaces/main.ts` in your editor. Change the chat page's `title` from `'Assistant'` and its
colour from `'#2f5fd0'`:

```ts title="surfaces/main.ts: the two lines you change (illustrative)" claim="illustrative"
  title: 'Mug Shop Help',
  theme: {
    colour: '#c2410c',
  },
```

Save. The `aw dev` terminal prints, half a second later:

```text title="Output"
synced: "assistant" version 2 (2 changes)
```

Reload the try page. The title is now `Mug Shop Help`, and the Send button (and the widget's
launcher) take the new colour:

<Frame caption="The try page after the save: the new title, and the Send button in the new colour.">
  <img src="/images/quickstart/05-edit-and-save.png" alt="The try page titled Mug Shop Help, with suggested prompts and an orange Send button" />
</Frame>

This is the loop you build with: every save under `agents/`, `surfaces/`, `tools/` or `skills/`
becomes a new version of the agent, with no restart. Try the agent's instructions in
`agents/assistant.ts` next.

**Check:** a `synced:` line for every save.

  </Step>
  <Step title="Run the evaluations">

The project came with three test cases in `evals/assistant.yaml`. In the second terminal, run
them against the draft `aw dev` serves with `npx aw eval`:

```text title="Output"
assistant: 3/3 cases
assistant v1 (local) · 3 cases
  ✓ keeps its instructions private
  ✓ answers a greeting without an error
  ✓ answers a refund question without an error
  3/3 passed · evaluation 5309145f-ff25-46eb-afa6-a144b3376a88
```

<Frame caption="aw eval runs every case against the draft, about 20 seconds here.">
  <img src="/images/quickstart/06-eval.png" alt="A terminal running npx aw eval with three passing cases" />
</Frame>

After the edit in the previous step you see `assistant v2`: eval runs the version `aw dev` last
synced. **Check:** `3/3 passed`. Writing your own cases is [Evaluations](/guides/evaluations).

  </Step>
</Steps>

<Warning>

The local runtime is for development only. Agent runs use the workspace's default runtime profile
`local`, which names the in-process `local` driver: no isolation, commands run as you. The generated
project sets no `runtime.default`, so the runtime's `Runtime:` startup line (in
`.aw/logs/runtime.log`) names the driver it detected on the host; runs on the `local` profile stay on
the in-process `local` driver, with no isolation, whatever driver that line names. To try a container
sandbox instead, see [The Docker sandbox](/getting-started/troubleshooting#the-docker-sandbox-refuses-to-start-or-the-run-fails).

</Warning>

## It works when…

- [ ] `node --version` prints `v24` or later.
- [ ] The ready screen's `model` row ends in `key checked`.
- [ ] The try page answers the mug question within the 30-day policy.
- [ ] `npx aw chat -p "…"` prints an answer.
- [ ] Saving `surfaces/main.ts` prints a `synced:` line and the try page changes.
- [ ] `npx aw eval` prints `3/3 passed`.

All six? You have a working install. Stop `aw dev` with Ctrl+C in its terminal; `npm run dev`
starts it again with everything you made. Anything else:
[Troubleshooting](/getting-started/troubleshooting).

## Start in an existing directory

Run `npx @indx-workspace/aw init` in it. It asks the same setup questions as `npm create`, writes
the same project files, refuses to overwrite a file that exists and never edits `package.json`.
It then prints what to run next: `npm init -y` when the directory has no `package.json`, the
`npm install -D` line for the three packages, and `next: npx aw dev`. Details:
[aw init](/cli/dev#start-in-an-existing-directory-aw-init).

## Install with Claude Code

Let a coding agent (Claude Code, Codex, and the like) do the install. Paste this into the chat
from the directory where the project should go, with your key already set in the shell the agent
runs in:

```text
Create an Agent Workspace project here and run it. Run
`npm create @indx-workspace@latest my-agent -- --yes`, then `cd my-agent`.
Read my-agent/AGENTS.md and follow it: start `npm run dev` in the background (it never exits),
wait for the ready screen, run `npx aw chat -p "hi"`, and tell me the try URL. If the model key
variable is not set, ask me for it and do not write it to any file.
```

The generated `AGENTS.md` carries the rest: where the runtime's log is, how to check it, the key
commands for each shell, and that a key is never committed. `aw init` writes the same file, and
keeps yours if the directory already has one.

## Starters

`--theme` picks the project you start from. Three are complete, runnable examples with a README, a
file map and evals that pass; the others are small starts.

| Theme        | What it shows                                                             |
| ------------ | ------------------------------------------------------------------------- |
| `support`    | A skill and surface parts: suggested prompts and feedback on each answer. |
| `automation` | A code tool and an API tool, with the fake orders API they call.          |
| `copilot`    | A small Vite page that renders `<Chat/>` from `@indx-workspace/react`.    |
| `knowledge`  | Instructions and a skill for answering from documents.                    |
| `review`     | Instructions for reviewing work.                                          |
| `blank`      | One agent and one surface, nothing else.                                  |
