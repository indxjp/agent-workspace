## What you can do

Claude Managed Agents runs your agent on Anthropic's side, in a cloud sandbox, with the Claude
loop. It is the closest match to an Agent Workspace agent: skills and subagents carry over as they
are. You can export the agent to the files the platform reads, and publish them with `ant`.

## Before you start

Only Claude models are accepted. A fresh project's agent names no model (it uses the `default`
model connection), and the export is refused with `platform_model_unsupported`. Set the model once,
under the platform's options:

```yaml title="agent-workspace.yaml (illustrative)" claim="illustrative"
platforms:
  claude-managed-agents:
    enabled: true
    options:
      model:
        id: claude-sonnet-4-6
```

The model id must start with `claude-`. The other options are optional:

| Option                    | What it does                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `model.id`                | Replaces the agent's model in every exported agent                                   |
| `model.effort`            | `low`, `medium`, `high`, `xhigh` or `max`                                            |
| `model.inferenceGeo`      | `us` or `global`                                                                     |
| `allowedHosts`            | Hosts the sandbox may reach when the agent has no unrestricted network               |
| `packages`                | Packages to pre-install: `apt`, `cargo`, `gem`, `go`, `npm`, `pip`                   |
| `mcpPermissionPolicy`     | `always_allow`, `always_ask` or `auto` for every MCP toolset                         |
| `toolsetPermissionPolicy` | The same three values for the built-in toolset                                       |

To publish you need Anthropic's `ant` command-line tool. Install it with
`brew install anthropics/tap/ant` (macOS) or
`go install github.com/anthropics/anthropic-cli/cmd/ant@latest`. When the export has vaults, version
1.34.0 or later is needed, otherwise 1.30.0. `ant` uses its own login; `aw` passes no credential.

## Export

```sh title="Export to Claude Managed Agents (illustrative)" claim="illustrative"
npx aw platforms export --platform claude-managed-agents
```

You get these files in `platforms/claude-managed-agents/`:

| File                                        | What it is                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------------- |
| `agents/<name>.md`                          | One per agent: the front matter is the agent, the body is the system prompt        |
| `skills/<skill>/…`                          | Each skill's files, copied and listed by path in the agents that use it            |
| `environments/default.yaml`                 | The sandbox: limited networking unless the agent has `unrestrictedNetwork`         |
| `vaults/<root>.yaml`, `aw-vault-credentials.json` | Only when an MCP server needs a credential: the names of the secrets it needs |

## What maps and what is dropped

These are the verdicts the Claude Managed Agents compiler writes to the export report, with the reason for
each. The [platform compatibility matrix](/platforms/matrix) shows what the platform supports, so
a cell there can differ from the verdict a field gets here:

| Your agent has…                    | On Claude Managed Agents                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| Instructions, description, model   | `native`                                                                              |
| Permissions                        | `mapped` to the sandbox tools: read, glob and grep; write and edit; bash; networking; a subagent's `unrestrictedNetwork` is dropped, `permissions_unsupported`, when the root agent's network is limited (the sandbox is shared) |
| Skills                             | `native`                                                                              |
| Subagents                          | `mapped` to predefined agents, up to 20, each in its own file; a listed agent's own subagents are dropped, `subagents_unsupported` |
| Remote MCP servers                 | `native` as an MCP server and toolset; `mapped` when it needs a credential, which goes to a vault |
| Remote MCP servers over SSE        | `mapped` as a url server; Managed Agents falls back to SSE for a server that does not speak streamable HTTP |
| Code tools                         | `mapped` to the project's MCP endpoint when you set one; otherwise dropped            |
| Web search, web fetch              | `native` as the `web_search` and `web_fetch` tools; with limited networking their results are limited to `allowedHosts` |
| Code execution                     | `mapped` to the sandbox shell, the `bash` tool                                        |
| File access                        | `mapped` to the sandbox file tools: read, glob and grep, plus write and edit when the agent may write files |
| Engine                             | dropped, `field_unsupported`; Managed Agents runs its own harness                     |
| Local (stdio) MCP servers          | dropped, `stdio_mcp_unsupported`                                                      |
| OpenAPI tools                      | dropped, `field_unsupported`                                                          |
| Knowledge                          | dropped, `knowledge_unsupported`; attach content to a session instead                 |
| Turn and budget limits             | dropped, `limits_unsupported`                                                         |

Subagent resolution by `ant apply` (the subagent's file path used as its agent id) is unverified
against a live tenant; the report marks it too.

A model that is not a Claude model is refused with `platform_model_unsupported`. An agent with more
than 20 MCP servers, or more than 20 subagents, is refused with `platform_limit_exceeded`.

## Publish

```sh title="Plan, then apply (illustrative)" claim="illustrative"
npx aw platforms publish --platform claude-managed-agents
npx aw platforms publish --platform claude-managed-agents --yes
```

Publishing runs `ant apply --dry-run` for the plan, then `ant apply --yes` with `--yes`. `aw` never
passes `--force`, so a resource that was changed in the Console blocks the publish instead of being
overwritten. How `aw` reads the plan's wording is taken from the vendor's documentation
(unverified against a live tenant); anything it does not recognise counts as a change.

Afterwards, commit `claude-lock.json` with the exported files: it records the ids `ant` created.

## Your tools

Remote MCP servers become MCP servers and toolsets in the exported agent. When one needs a
credential, the export writes a vault and `aw-vault-credentials.json`, which holds secret names,
never values; add the credentials yourself in the Claude Console. `mcpPermissionPolicy` sets
whether each MCP toolset may run without asking.

To reach your code tools, add `publicBaseUrl` and `toolAuth`
([how that works](/platforms/overview#your-code-tools-on-another-platform)). Without them every
code tool is dropped with `code_tool_needs_public_mcp`.

## What is not there yet

- How `aw` reads the `ant apply --dry-run` plan is unverified against a live tenant.
- Subagent resolution by `ant apply` (the subagent's file path used as its agent id) is unverified
  against a live tenant.
- A manual live lane in the repository's CI publishes an agent to Managed Agents with the real `ant`
  and removes it again. It runs only on demand. Until a run of it passes, publishing to Claude
  Managed Agents is unverified against a live tenant.
- Knowledge, OpenAPI tools, local (stdio) MCP servers and turn and budget limits are dropped.
