<Info>
- **Read this when:** you are choosing a platform, or you want to know why a field was dropped in a `PLATFORM_REPORT.md`.
- **You will learn:** which capabilities each platform carries as they are, which it translates and which it cannot carry.
- **Used in:** [Chapter 7: Run it on other platforms](/path/platforms).
</Info>

Each column is one value of `--platform` in `aw platforms export`. Read a cell as the answer to
"what happens to this field of my agent when I export it there?". The export itself always tells you
field by field in its `PLATFORM_REPORT.md`; this page is the same answer for all platforms at once.

## Legend

| Cell | Verdict | Meaning |
| ---- | ------- | ------- |
| `✓`  | native  | The platform has the capability and the field is carried as it is. |
| `≈`  | mapped  | The field is translated, and the report says how. |
| `-`  | dropped | The platform cannot carry it. The field is dropped and the report names the drop code. |

The **Import** row is `✓` when `aw platforms import --from <id>` can read that platform's own
files back into a portable project; a target without an importer shows `-`. The **Conformance**
row is `✓` when the target passes the shared conformance run that every platform target must pass.

## Two names that look alike

`aws-agentcore` is a platform id here: the Amazon Bedrock AgentCore harness an agent is published
to. It is also the id of a runtime driver, where it names the sandbox a run executes in. They are
different things that share a name; see [AWS AgentCore](/platforms/aws-agentcore).
