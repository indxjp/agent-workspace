# `@indx-workspace` packages 0.6.12 release notes

Release status: **published from the `packages-v0.6.12` tag.** These notes describe the lock-step
0.6.12 release of the eight npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`,
`aw`, `cli`, `embedded`, `create`), cut from a `packages-v0.6.12` tag by
`.github/workflows/publish-packages.yml` once the platform images `images-v0.6.12` are public
([release procedure](../README.md#npm-packages)). This page says what landed since
`packages-v0.6.11`; each package's `CHANGELOG.md` lists the detail under its 0.6.12 heading.

It records every storage adopt and skills pass as migration proof, finishes Storage v1.1, and adds
per-workspace feature switches and agent archiving. 0.6.12 is a **required upgrade stop** for
self-hosted installs; read "Before you upgrade".

## Before you upgrade

- **0.6.12 is a required upgrade stop.** Every self-hosted install must start 0.6.12 once, with
  `AW_STORAGE_MIGRATE` unset, and let the storage adopt pass and skills pass both finish clean
  before it takes any later release. From this release each pass writes a row to
  `storage_migration_runs` with `proof_version` 2 (migration `0091`), a failed or unchanged pass
  included; rows written by 0.6.11 or earlier carry no proof version and do not count. The next
  release adds migration `0093_storage_proof_guard`, which refuses the upgrade until the latest
  `adopt` row and the latest `skills` row are clean v2 proof. An install that skips 0.6.12 has no
  such rows and cannot upgrade past it. To check, the latest row of each stage must read
  `clean = true` and `proof_version = 2`:
  ```sql
  SELECT DISTINCT ON (stage) stage, clean, proof_version, orphans, finished_at
  FROM storage_migration_runs WHERE stage IN ('adopt', 'skills')
  ORDER BY stage, finished_at DESC;
  ```
  `orphans` on the skills row counts files of skill revisions with no committed revision record;
  they are left in place for review and do not make the pass unclean.
- **Session-state blobs need the storage service.** `PUT` of a session-state blob answers
  `session_state_blobs_not_configured` while the files API is not serving (`AW_STORAGE_URL` unset,
  or the storage service or its catalog failed to open), instead of saving outside it.
- **Storage connection credentials are bound to their target.** Revisions up to 0.6.11 cannot read a
  credential stored this way and refuse the connection. Drain older revisions before you create,
  edit or rotate a storage connection (self-hosting guide). After deploying, restart running tool
  sandboxes, and rotate the credential of any storage connection whose `STORAGE_CONNECTION_` secret
  a code tool could have named.
- **PostgreSQL 18.** The repository `compose.yaml`, new Compose deployments and the local runtime of
  `aw dev` run PostgreSQL 18. A data directory a 17 server created does not open under 18: `aw dev`
  stops with `data_directory_version`; dump a Compose volume with the 17 image first, or start
  empty. `render --upgrade` never moves an existing `POSTGRES_IMAGE`.
- **A GCS key must name its type.** A GCS storage connection whose stored service-account key does
  not give `service_account` as its `type` no longer opens (`storage_connection_url_invalid`).
  Rotate its credential with the key file Google Cloud issued, which carries the `type`, with
  `aw storage connections credential`.
- **Clients and server move together.** `GET /api/me` now carries a required `features` key, and a
  project file may carry `features:`; an SDK, `aw` or contracts release older than 0.6.12 rejects
  both. Deploy the gateway before, or with, the web service, so it knows the daily-cost-cap run
  token claim.

## Storage

- Every adopt and skills pass is recorded in `storage_migration_runs` with `proof_version` 2, the
  migration proof the next release checks.
- A signed upload link can no longer change a file after its upload completed: completion copies
  the upload into an object no link was signed for. A replacement upload is authorized against the
  file the catalog reserved under its path lock.
- A run's write-back keeps every path its launch delivered read-only, and stops before its next
  file once the run is no longer running.
- `aw files upload` and `files.upload(path, stream, { sizeBytes })` stream instead of buffering;
  `files.upload` honours an abort `signal`.
- New `429` codes for signed links (`too_many_pending_uploads`, `link_rate_limited`), the Helm
  chart's `storage.url`, an Azure sovereign-cloud blob endpoint, and a series of adapter, listing,
  archive and runner-proxy fixes.
- Files answer `lastModified`; a folder move answers the number of files it moved; a Builder can
  delete its own pending upload. A refused `POST /files` hydrate leaves the run workspace as it was.
- Proven against live AWS S3, Google Cloud Storage and Azure Blob. That proof fixed an Azure signed
  link minted for a past time, a GCS write whose source fails, and a GCS signing window that is
  already over, which is now a typed refusal. An S3 connection's `publicEndpoint` and an Azure
  connection on its default host pass the outbound check.
- A Claude engine translation refusal answers `engine_policy_invalid` on the run's error frame;
  the OpenAPI document describes `POST /api/skills` multipart.

## Features and agents

- A route whose feature the deployment does not install (`AW_DEPLOYMENT_FEATURES`) or the
  workspace switched off answers `404 feature_disabled`. `GET`/`PUT
  /api/workspaces/:id/features`, `workspaces.features.list/set` and `aw workspaces features` list
  and switch them; `create` and `aw init` accept `--features`.
- Agents an agent made are archived after 30 unused days; an archived agent refuses runs with
  `409 agent_archived`. `POST /api/agents/:id/restore`, `agents.restore(id)` and
  `aw agents restore` bring one back.
- The Builder is provisioned per workspace, runs on a fresh install, and is switched by the
  workspace's `builder` feature. Names in `builder.allow` are reserved for Owners and Admins
  (`403 builder_name_reserved`), and a running run over `maxCostPerDayUsd` stops at its next model
  call.
