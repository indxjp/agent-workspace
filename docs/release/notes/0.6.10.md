# `@indx-workspace` packages 0.6.10 release notes

Release status: **published from the `packages-v0.6.10` tag.** These notes describe the lock-step
0.6.10 release of the eight npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`,
`aw`, `cli`, `embedded`, `create`), cut from a `packages-v0.6.10` tag by
`.github/workflows/publish-packages.yml` once the platform images `images-v0.6.10` are public
([release procedure](../README.md#npm-packages)). This page says what landed since
`packages-v0.6.9`; each package's `CHANGELOG.md` lists the detail under its 0.6.10 heading.

It is a patch release with no breaking contract change. Its main content is the new storage layer.

## Move to `AW_STORAGE_URL`

Storage is now set with one variable, `AW_STORAGE_URL` (#1770), for example
`s3://my-bucket?region=eu-west-1` or `file:///var/lib/agent-workspace/storage`; the schemes are
`file`, `s3`, `gcs` and `azblob`.

- **In 0.6.10 the old settings still work, with a deprecation warning.** That covers
  `OBJECT_STORAGE_BACKEND`, `OBJECT_STORAGE_ENDPOINT`, `OBJECT_STORAGE_BUCKET`,
  `OBJECT_STORAGE_FORCE_PATH_STYLE` and the per-area roots (`AW_FILE_STORAGE_ROOT`,
  `AW_SKILL_STORAGE_ROOT`, `AW_SESSION_TRANSCRIPT_ROOT`). Setting the URL and an
  old variable that disagree is refused.
- **The next release ignores them** and logs a `storage_setting_ignored` warning instead. Move to
  `AW_STORAGE_URL` now: `agent-workspace doctor` shows the URL that replaces your old variables,
  and the [self-hosting page](../../sdk/site/features/self-host-securely.mdx) maps each old
  variable to the URL.
- `create` writes `AW_STORAGE_URL` for new local, AWS and GCP projects, and the Terraform modules
  and `agent-workspace deploy` (Vercel, Cloudflare) set it.

## Other storage changes

- **Files catalog.** Every stored file has a catalog row. Listing, search, rename and move read and
  update rows instead of copying bytes, and downloads stream from the object store instead of
  being held in memory. At start-up the server gives files stored the old way a row in the
  background (`AW_STORAGE_MIGRATE=adopt`, the default; `off` disables it).
- **Large uploads.** Signed upload links take files up to `AW_STORAGE_SIGNED_UPLOAD_MAX_BYTES`
  (default and maximum 5 GiB) instead of 64 MiB; the Files screen, the SDK and the CLI use them
  for large files.
- **Storage connections (bring your own bucket).** Owners and Admins can connect an S3 bucket or
  an allowed local folder at `/admin/storage` or through `/api/storage-connections`, read-only by
  default, with credentials sealed and never returned. An agent can be granted one folder of a
  connection with `files('storage://<connection>/<folder>')`; with `read-write` access a completed
  run writes its new and changed files back to that folder.
- **Doctor.** `agent-workspace doctor` reports the storage setting and a `storage-layout` check
  that counts objects still in the old per-area layout.
- **Cleanup.** A storage cleanup pass runs hourly in report mode (`AW_STORAGE_CLEANUP=report`, the
  default); `delete` removes objects no file row points at.

## Also in this release

- Triggers can ask for a structured answer (`outputSchema`) and are managed with `aw triggers`.
- `aw agents export --format ts` writes an agent as `defineAgent` files.
- Security updates: Next.js 16.4.2 and Node 24.22.1, plus the October dependency refresh.
