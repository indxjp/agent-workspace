# `@indx-workspace` packages 0.6.3 release notes

Release status: **published on npm on 2026-10-12.** These notes describe the lock-step 0.6.3 release of the eight
npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`, `aw`, `cli`, `embedded`,
`create`), cut from a `packages-v0.6.3` tag by `.github/workflows/publish-packages.yml` once the
platform images `images-v0.6.3` are public ([release procedure](../README.md#npm-packages)).

This page says what landed since `packages-v0.6.2`; each package's `CHANGELOG.md` lists the detail
under its 0.6.3 heading.

It is a patch release: the contract changes are additions (public-surface policy), so
`@indx-workspace/sdk@0.6.x` and `@indx-workspace/aw@0.6.x` both speak contracts 0.6. The one new
contract export is `EXTERNAL_RUNTIME_PROVIDERS` (with `ExternalRuntimeProvider`) in
`@indx-workspace/contracts/runtimes`.

## Fixes

- **Skill scripts run under a read-only file grant.** A run that holds a read-only file grant has
  its shell withheld, so an agent that called its skill's Node script through `Bash` could not run
  it. The new `run_skill_script` tool runs a skill's script with no shell, under Node's permission
  model: it reads the run's folder and writes only its scratch folder and read-write grants, with a
  120 s timeout, 1 MiB of output per stream and no stdin, while `Bash` stays denied (ADR-0137). It
  is live on the Claude Agent SDK and Mastra engines; the OpenAI Agents engine still refuses skills,
  so the tool has nothing to run there. The contract-review, quality-defect, cad-drafting and
  meeting-minutes gallery agents call their scripts through it (#1093). Its containment check is
  correct on Windows, where every call was refused as `outside_skill_directory` (#1096).
- **Runs find `node`.** A run's subprocess got no `PATH`, so a `node` installed through nvm, volta,
  Homebrew or a CI toolchain was not found ("Node.js unavailable"). The runner now passes a minimal
  environment: `PATH` and `HOME` on POSIX (`PATH`, `USERPROFILE`, `SystemRoot` and `TEMP` on
  Windows). Provider keys and other deployment variables still do not cross, and the request's own
  `env` still wins (#1091).
- **E2B agent sandboxes have a bounded life.** On the `external` (E2B) driver, a session's agent
  sandbox lived until the plan maximum (an hour on Hobby, a day on Pro), so abandoned sessions used up
  the provider's sandbox limit. Its timeout is now the larger of the session idle time (900 s) and
  the spec's `idleTimeoutSeconds`, plus 120 s, capped at the plan maximum, and each reuse renews it:
  an abandoned session frees its slot after about 17 minutes. A spec with a hard `timeoutSeconds`
  and tool sandboxes keep their timeouts (#1078).
- **The A2A agent card is public.** `GET /api/a2a/agents/<name>/.well-known/agent-card.json` without
  credentials now serves the card of a published agent of the deployment's workspace (rate limited
  per client address), which is what Gemini Enterprise and `aw platforms publish --platform
  gemini-enterprise` fetch. Unknown, unpublished and other-workspace agents get the same 404, and
  every other A2A route still answers 401 without credentials (#1081).
- **Gallery.** excel-consolidation ships its twelve branch workbooks, so the agent finds them;
  contract-review ships its contract drafts as `.docx` in `contracts/`; maintenance-troubleshooting
  gives one step per reply, also in its first reply. A run-time access test checks, for each gallery
  agent, that every uploaded file is under a grant and that no pre-approved tool is denied (#1087,
  #1091).

## What changed since 0.6.2

- **`provider: e2b` on `external` runtime profiles.** `runtime.provider` is accepted with
  `driver: external` in `agent-workspace.yaml` and its JSON Schema; absent means `e2b`, as before.
  An unknown provider is refused by name, and `POST`/`PATCH /api/runtime-profiles` refuse it with
  `422 runtime_provider_unsupported` (#1078).
- **Publish to Microsoft Foundry.** `aw platforms publish --platform microsoft-foundry` gets its
  token from `az account get-access-token` (never printed), shows the plan of agents to create or
  update, and sends nothing without `--yes`. The Foundry options take `projectEndpoint`. Project
  connections are listed as next steps, and `aw platforms publish` prints those steps before it exits
  `3` for pending changes. The Copilot Studio zip is written next to the export folder
  (`platforms/<solution>.zip`), not inside it (#1079).
- **Platform reports.** A report for two or more agents is grouped under a `Project` heading and one
  heading per agent; a one-agent report is unchanged. `gemini-enterprise` reports a root agent's
  generated description as `mapped`, quoting it (#1088).
- **Deploy guides and live checks.** New guides for Vercel and Cloudflare (#1077). A live journey run
  verified on both that `aw promote` is refused below the eval bar and that a turn through the
  project frontend completes with the code tool's data (#1092).
- **Docs chapter 7, "Run it on other platforms"**: an overview, one guide per agent platform, eject,
  switching the engine and the compatibility matrix. The Foundry guide covers publish (#1074, #1085).
- Tests only: a platforms journey with golden verdicts for every platform, and a manual live lane
  that publishes to Claude Managed Agents and removes what it created (#1075, #1080, #1086, #1094).
