# `@indx-workspace` packages 0.3.0 release notes

Release status: **published on npm on 2026-10-04.** These notes describe the lock-step 0.3.0
release of the six npm packages (`@indx-workspace/contracts`, `sdk`, `aw`, `cli`, `embedded`,
`create`), cut from a `packages-v0.3.0` tag by `.github/workflows/publish-packages.yml`
([release procedure](../README.md#npm-packages)). `npm create @indx-workspace@latest` writes the
project below. They are not the platform release (`v*` tags,
[`docs/release/notes/0.1.0.md`](0.1.0.md)). Each package's `CHANGELOG.md` has the detail;
this page says what works and what does not yet (issue #608).

## What works

Proven by the developer-journey CI job (`tests/journey/run.mjs`) with packages packed from this
repository and a stub Anthropic API, and after the publish by the same journey against
`registry.npmjs.org` ([post-publish smoke](../README.md#post-publish-smoke)).

- **Get it.** `npm create @indx-workspace@latest demo -- --yes`, then `npm install` and
  `npm run dev`, writes a v2 project and starts the local runtime: `aw dev` prints `ready <url>`,
  signs in, and the widget at `/p/s/main/try` answers. `@indx-workspace/embedded` is on npm for the
  first time, so `npm install` no longer fails with E404. Without `--yes` the setup questions are asked
  on a terminal.
- **Make it mine.** `aw dev` syncs `agents/`, `surfaces/` and `tools/` to `local` on every save; a colour in
  `surfaces/main.ts` reaches the widget. A hand-written tool in `tools/`, or `openapiTool()` over
  your own OpenAPI document, is called by the agent with a secret that stays in the sealed store.
  `aw init`, `aw check` and `aw push [--yes]` work on the same files.
- **Ship it safely (partly).** `AGENT_ENVIRONMENTS` has `production` beside `local`, and an agent's
  version listing carries its last ten pointer moves. `aw eval` runs `evals/<agent>.yaml` against a
  version and the server scores and stores the result.
- **Promote and roll back.** `aw promote`, `aw rollback` and `aw versions` move and list an agent's
  environment pointers, with matching SDK methods (#654).
- **Learn from it.** `aw feedback` lists the ratings of an agent's runs, and `aw eval add-case`
  turns a thumbs-down into an eval case.
- **Put it in front of users (first step).** `aw deploy production [--plan | --yes]` takes a v2
  project's `environments.production` (`target: single-vm`) to a Compose deployment through
  `agent-workspace deploy`; it needs the platform images 0.3.0.
- **Deploy to Cloud Run.** `aw deploy` also takes `target: gcp-cloudrun`, and the Deploy guide walks
  through it (#656).
- `npm create @indx-workspace <dir> -- --cloud local` still writes the v1 Compose project.

## What does not work yet

- **No upgrade path from 0.2.1.** A 0.2.1 project is not migrated (B8, in the remaining 20 %).
  Generate a new project.
- **Every recorded time uses a stub model.** The nightly live-model journey is separate (#609).
- **Not in this release** (issue #608): signed images and an upgrade path from 0.2.1.
- **Not finished on `main` at this release:** the versions tab (#617), the promotion gate (#619), serving a surface to the public on a real site (#622) and
  `@indx-workspace/react` (#623). A package changelog entry is the only claim that part of one
  ships.
- **No npm provenance** while the repository is internal (ADR-0082 D5).

## Compatibility

`CONTRACTS_VERSION` moves to 0.3.0, a minor: a 0.3 control plane still serves 0.2 clients (one minor
back), and a 0.2 client refuses a served shape that only 0.3 has (a tool connector, a `production`
pointer, pointer moves) with `ContractViolationError`. See the contracts changelog.
