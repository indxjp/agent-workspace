# `@indx-workspace` packages 0.6.11 release notes

Release status: **published from the `packages-v0.6.11` tag.** These notes describe the lock-step
0.6.11 release of the eight npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`,
`aw`, `cli`, `embedded`, `create`), cut from a `packages-v0.6.11` tag by
`.github/workflows/publish-packages.yml` once the platform images `images-v0.6.11` are public
([release procedure](../README.md#npm-packages)). This page says what landed since
`packages-v0.6.10`; each package's `CHANGELOG.md` lists the detail under its 0.6.11 heading.

It completes the move to `AW_STORAGE_URL` that 0.6.10 announced, and it carries the first
Builder work. Several platform changes are breaking; read "Before you upgrade".

## Before you upgrade

- **The old storage settings are ignored.** `AW_FILE_STORAGE_ROOT`, `AW_SKILL_STORAGE_ROOT`,
  `AW_SESSION_TRANSCRIPT_ROOT` and the `OBJECT_STORAGE_*` variables no longer say where files,
  skills and session state are kept; only `AW_STORAGE_URL` does. A leftover old variable never
  stops start-up: the server, `agent-workspace doctor`, `aw dev` and the Vercel and Cloudflare
  deploy commands log one `storage_setting_ignored` warning that names it. The repository
  `compose.yaml` and a generated Compose project refuse to start without `AW_STORAGE_URL`.
- **Migrate stored files first.** `db:migrate` refuses to run while a `files` or
  `session_state_blobs` row still has no `object_id`. On 0.6.10, start once with
  `AW_STORAGE_MIGRATE=copy` and wait for a progress line with `"done":true`, then upgrade.
- **Files, skills, attachments and run delivery read and write only through the catalog service.**
  A deployment whose catalog service cannot start answers 503 instead of serving from an area root.
- **Run protocol.** The runner refuses inline `contentBase64` file and skill contents; web servers
  older than 0.6.10 cannot drive runners from this release.
- **Images registry.** Platform images publish to `ghcr.io/indxjp/agent-workspace/*` from the
  public repository, for every release after 0.6.10. The npm packages carry npm provenance.

## Storage

- `@indx-workspace/contracts/storage-settings` keeps every export of the old settings as a
  deprecated shim (removed in the next major release), and adds `ignoredStorageVariables`.
- Storage connections accept S3 temporary (STS) credentials with a `sessionToken` and GCS
  short-lived access tokens; `AW_STORAGE_CREATE_BUCKET=true` creates the bucket of an `s3://`
  `AW_STORAGE_URL` on first boot.
- The start-up migration also gives skills kept in the old forms a catalog row.
- New guide: "Use your own bucket" (S3, Google Cloud Storage, Azure Blob or a local folder).

## Deprecated

The JSON + base64 skill import (`ImportSkillInput`, `skills.import` with `contentBase64`) is
deprecated in favour of `multipart/form-data`, and is removed in the next major release. The
server answers with a `Deprecation` header; `aw push` and `aw dev` no longer use it.

## Builder

Available once an admin enables the `builder` feature for the workspace.

- The Builder saves approved drafts (`draft_save`), tries them (`trial_run`, capped at 0.30 USD)
  and scores them (`evals_run`); each runs only after you approve it. A save lands on `local`,
  never on `production`, and writes an `agent-created` audit row, which now names the Builder run
  (`builderRunId`).
- The new-agent page has a Form | Chat switch with approval cards and saved-version links;
  `aw agents new --from-prompt` does the same on a terminal.
- `POST /mcp/builder` gives an outside MCP client read-only access to the catalogue, examples and
  draft checks; `aw endpoint-clients create --kind builder` creates its client.
- Agents named in `builder.allow` of the deployment policy can build from their own run, within a
  daily creation quota; `AgentResource` records `createdByAgent` and `archivedAt`.

## Also in this release

- `policy.maxCostPerDayUsd` sets a daily model-spend cap, enforced at run start.
- `diffBodies` in `@indx-workspace/sdk/portable` also diffs policy, subagents, knowledge and
  description.
