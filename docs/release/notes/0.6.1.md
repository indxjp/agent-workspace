# `@indx-workspace` packages 0.6.1 release notes

Release status: **published on npm on 2026-10-11.** These notes describe the lock-step 0.6.1 release
of the seven npm packages (`@indx-workspace/contracts`, `sdk`, `react`, `aw`, `cli`, `embedded`,
`create`), cut from a `packages-v0.6.1` tag by `.github/workflows/publish-packages.yml` once the
platform images `images-v0.6.1` are public ([release procedure](../README.md#npm-packages)).

0.6.1 is the first npm release of the 0.6 line. 0.6.0 was cut as platform images only
(`images-v0.6.0`); its packages were never published, and image tags are immutable, so the images
and packages of 0.6.1 are built from the same commit. Everything in the
[0.6.0 notes](0.6.0.md) ships here, and each package's `CHANGELOG.md` lists 0.6.0's
entries under its 0.6.1 heading. This page says what landed since 0.6.0 was cut.

It is a patch release: the contract changes are additive (public-surface policy). New deploy
targets, error codes, evaluation-run schemas and the network-policy floor are additions, and no
schema rejects a body it accepted in 0.6.0, so `@indx-workspace/sdk@0.6.x` and
`@indx-workspace/aw@0.6.x` both speak contracts 0.6.

## What changed since 0.6.0

- **Deploy to Vercel and Cloudflare.** `deploy` gains the `vercel` and `cloudflare` clouds
  (ADR-0120): the gateway, runner manager and frontend run as Vercel functions or Cloudflare
  Workers and containers, with a migrate-once step, cron retention and an object store for skills.
  A `kubernetes` deploy target and the `gcp-cloudrun` module ship alongside.
- **E2B, Vercel and Cloudflare sandboxes.** Agent sessions run on an external driver with an E2B
  provider, a `vercel-sandbox` driver and a `cloudflare-sandbox` driver with its bridge Worker, and
  on the kubernetes driver in a cluster. The pinned E2B runtime template is built in CI.
- **Tool sandbox.** Code tools are bundled at `aw push`, stored with the agent version and run in a
  per-session tool sandbox, off by default (ADR-0118), locally (`aw dev --sandbox docker`) and in
  deployments, including on E2B. Stdio MCP connectors are meant to run there too, but no
  environment launches them yet (issue #793): a local run goes ahead without their tools.
  `aw tool call` and `aw runs trace` show what a tool did; the console promotes and rolls back
  code-tool versions.
- **Egress.** An allowlist egress proxy (ADR-0117) carries docker and kubernetes sandbox traffic;
  `unrestrictedNetwork` sets the sandbox network floor (ADR-0119), and a network policy a driver
  cannot enforce is refused with a typed error.
- **Evaluations and operations.** Larger async evaluation runs with CI-friendly output, deployments
  that carry the eval gate, migrations that run once under an advisory lock, and upgrade, rollback
  and backup runbooks. A scripted model provider gives offline, deterministic runs.
- **Setup without a person.** Every interactive step of `create` and `aw init` is settable by a
  flag, and nothing waits for input when no one is there. The unimplemented `sandbox-runtime`
  driver is no longer offered.
- **Fixes.** Typed setup and runtime-test failures, the sandbox provider credential carried through
  Test Runtime and release, Vercel function builds and `.env` handling, Cloudflare readiness and
  retries, the runner's Docker CLI bumped for Go stdlib CVEs, and patched `sharp` and
  `@modelcontextprotocol/client` overrides. Correction: those overrides apply to the images and
  this repository only. A project generated by 0.6.1 still installs
  `@modelcontextprotocol/client@2.0.0` (GHSA-6qxp-vccf-f47h, high), which `@mastra/mcp` pins
  exactly; add `"overrides": { "@modelcontextprotocol/client": "^2.2.0" }` to its `package.json`.
  Later releases generate the overrides into the project (BH061-007).
