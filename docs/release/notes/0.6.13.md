# `@indx-workspace` packages 0.6.13 release notes

Release status: **published from the `packages-v0.6.13` tag.** These notes describe the lock-step
0.6.13 release of the nine npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`,
`app`, `aw`, `cli`, `embedded`, `create`), cut from a `packages-v0.6.13` tag by
`.github/workflows/publish-packages.yml` once the platform images `images-v0.6.13` are public
([release procedure](../README.md#npm-packages)). This page says what landed since
`packages-v0.6.12`; each package's `CHANGELOG.md` lists the detail under its 0.6.13 heading.

It is the first release past the 0.6.12 upgrade stop: the server no longer reads the old object
naming, and `db:migrate` refuses an install that has not proven the move on 0.6.12. It also adds
the app kit (`@indx-workspace/app`, published for the first time), agent teams, run-outcome
webhooks, the one-command Google Cloud install, and a Japanese console.

## Before you upgrade

- **Upgrade from 0.6.12 only.** This release adds migration `0093_storage_proof_guard`. Its
  `db:migrate` refuses with `legacy_storage_rows_remain`, and changes nothing, unless the latest
  `adopt` row and the latest `skills` row of `storage_migration_runs` both have `proof_version` 2,
  `clean` true and `legacy_rows` 0, and no file or session-state blob row lacks an object id. Only
  0.6.12 writes such rows, so an install on 0.6.11 or earlier goes 0.6.11 → 0.6.12 → 0.6.13. On
  0.6.12, start it once with `AW_STORAGE_MIGRATE=copy`, once with `AW_STORAGE_MIGRATE=finalize`,
  and once with it unset, then check before you upgrade:
  ```sql
  SELECT DISTINCT ON (stage) stage, proof_version, clean, legacy_rows, orphans, finished_at
  FROM storage_migration_runs WHERE stage IN ('adopt', 'skills')
  ORDER BY stage, finished_at DESC, id DESC;
  ```
  The self-hosting guide names a remedy for each cause that keeps `legacy_rows` above 0
  (`skipped_ownerless`, `skipped_path_taken`, `skipped_failed`, a skill whose delete is pending).
  A fresh install has nothing to move and upgrades with no step. After the check, a file row and a
  session-state blob row must name an object id (`files_file_has_object_id`,
  `session_state_blobs.object_id NOT NULL`).
- **The old object naming is gone.** The server opens, lists and deletes files and session-state
  blobs only by object id, and the `adopt`, `copy`, `copy-dry-run` and `finalize` stages of
  `AW_STORAGE_MIGRATE` are removed (`off` still turns off the skills adopt pass). An object only
  the old naming reached is not listed; `agent-workspace doctor` drops its `storage-layout` check.
- **Start-up refuses settings it used to ignore.** `web` exits with status 1, naming each refused
  variable, on an invalid `AW_DEPLOYMENT_POLICY`, `AW_DEPLOYMENT_FEATURES`,
  `AW_TRUSTED_PROXY_HOPS` (not `0` to `16`) or `AW_CONTAINER_IDLE_STOP_SECONDS` (not whole seconds
  above 15), instead of answering 500 or reading a malformed proxy count as none. The gateway stops
  before it opens the database without a valid `GATEWAY_PRICING_JSON`; the runner manager names a
  missing driver setting and exits, and `RUNTIME_VERIFICATION_TIMEOUT_MS` must be a whole number
  of milliseconds. `docs/operations/settings.md` lists every variable.
- **Public share links are shown once.** Migrations `0104` and `0105` store only the SHA-256 of a
  link's token and clear the plain tokens; existing links keep working. `GET /api/shares`,
  `shares.list()` and `aw shares list` no longer carry a `url`: keep the one `POST /api/shares`
  returns. A contracts, SDK or `aw` release older than 0.6.13 refuses a public list item without
  `url`, and 0.6.13 refuses one with it, so clients and server move together. The plain `token`
  column stays one more release, so a 0.6.12 web process can still publish during a rolling update.
- **Run commands asks before a change.** With **Run commands** on, a shell command that changes
  something now pauses the run for Approve or Reject, where before it was refused with nobody
  asked. With **Write files** on, an agent writes in its workspace without asking, except
  `CLAUDE.md`, `.claude/` and `.mcp.json`, which need approval. A run paused for approval is
  cancelled with `approval_expired` after 24 hours.
- **Other refusals that changed.** A `429 daily_cost_cap_reached` run start carries `capUsd` and
  `resetsAt`, no longer `spentUsd`. The OpenAI Agents, Mastra and pi adapters no longer enforce
  `limits.maxBudgetUsd` themselves: the gateway does, for every engine (ADR-0162).
- **Sessions survive.** `SESSION_SECRET` now derives one key per purpose with HKDF; tokens signed
  the old way are accepted until they expire (at most 12 hours), so nobody is signed out.

## Storage

- Session-state saves reserve a row, stream the body and confirm on a token, like file saves.
- A `file://` connection follows a directory symlink inside its folder on Linux, holds conditional
  writes across processes with a lock file, and refuses NTFS-reserved names on Windows.
- Testing a storage connection looks into every allowed folder and names the empty ones; Connect
  storage saves and then tests in one step.
- Migration `0102` gives a version materialised during the upgrade window the grants its agent
  holds, so it no longer fails with `run_storage_grant_unavailable`.

## Agents and runs

- Agent teams (ADR-0104): `/api/agent-teams/**`, `aw.agentTeams` and `aw agent-teams`; a lead calls
  each member as the tool `agent__<member>`, and run trees show on the run read and in the console.
- Run-outcome webhooks: `/api/webhooks`, `aw.webhooks`, `aw webhooks` and
  `verifyWebhookSignature`. Run starts honour `Idempotency-Key`, and `runs.follow` backs off between
  reconnects.
- A run stops at its spend ceiling on every engine, and a lower-only limits override (a Builder
  trial's budget) survives an approval continuation (migration `0101`).
- An agent may keep a memory folder across sessions (ADR-0163); a schedule's time can be changed in
  place (`triggers.update`, `aw triggers update`).
- `aw push`, `aw check` and the first sync of `aw dev` accept an agent that names a built-in skill
  (`office-reader`) the workspace has not installed yet; their dry run used to refuse it with
  `agent_definition_references_missing` (#2310).

## App kit and apps

- `@indx-workspace/app` joins the lock-step set: resources, generated routes and pages, agent
  panels, realtime channels, the dashboard, recipes and blueprints, with the `aw-app` bin.
- `aw generate app|resource|page|channel|recipe|agent`, `aw destroy` and `aw blueprint`;
  `npm create @indx-workspace <dir> -- --template portal|chat|wiki|crm|desk`.
- An app backend signs a person in by token exchange (`POST /api/auth/token-exchange`,
  `aw.auth.exchange`, ADR-0161); `aw dev` runs a development OIDC issuer when no `OIDC_*` is set.
- `environments.production.apps` deploys apps on single-vm, Kubernetes and Google Cloud Run.
- A Cloud Run app can sign people in: set `signIn` on the app (its client id at `gcp.oidc` and
  its `app-backend` endpoint client, with Secret Manager ids for both secrets) and deploy again;
  `aw deploy` prints the redirect URI to register. Before, it answered `sign_in_not_configured`
  (#2331).

## Deployment

- `aw deploy production` with a `gcp` block installs the whole workspace into your Google Cloud
  project: private by default, Claude on Vertex AI with no stored key, sandboxes with no internet
  (or `restricted` and `open` through an egress proxy), code tools in tool sandboxes, data
  protection, sizes, monitoring and `aw deploy status`.
- A CLI release pins every platform image by digest and, when `cosign` is installed, verifies its
  signature before a deploy; an image override prints a warning.

## Console

- The console speaks Japanese to a Japanese reader on its main screens, and follows the viewer's time
  zone.
- Approve and Reject in the chat, recent chats under New chat, a Sign out button, a Schedules tab,
  folder uploads and search on Files, and the files a run wrote on the run view.

## Also in this release

- `aw dev` starts the embedded PostgreSQL from a Windows account with administrator rights, through
  the bundled `pg_ctl.exe`; where that is refused too, it stops with `windows_administrator`, naming
  a non-elevated terminal or `DATABASE_URL` as the fix (#2330).
- The gallery's meeting-minutes, ringi-review and maintenance-troubleshooting projects push again,
  and the guides create a connector's identity secret with `aw secrets create` (#2311).
- Anthropic API connections declare prompt caching, verified live.
- An ejected Claude Agent SDK project writes files in `workspace/` and keeps its skills in
  `workspace/.claude/skills/`.
