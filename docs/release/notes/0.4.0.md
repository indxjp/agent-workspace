# `@indx-workspace` packages 0.4.0 release notes

Release status: **published on npm on 2026-10-05.** These notes describe the lock-step 0.4.0 release
of the seven npm packages (`@indx-workspace/contracts`, `sdk`, `react`, `aw`, `cli`, `embedded`,
`create`), cut from a `packages-v0.4.0` tag by `.github/workflows/publish-packages.yml` once the
platform images `images-v0.4.0` are public ([release procedure](../README.md#npm-packages)).
They are not the platform release (`v*` tags, [`docs/release/notes/0.1.0.md`](0.1.0.md)).
Each package's `CHANGELOG.md` has the detail; this page says what changed since
[0.3.0](0.3.0.md) and what does not work yet (issue #607).

## What is new since 0.3.0

- **A missing or rejected model key says so.** `aw dev` checks the key of each model connection at
  start and prints a `warning:` naming the variable to set (never its value); the try page shows
  the same banner before the first message; `aw runs` and `aw eval` add a `fix:` line, and report
  a case by its code (`model_credential_rejected`, `model_connection_failed`) instead of
  `run_failed`. A rejected key now fails a run in seconds, not after minutes of retries
  (#661: #672, #676, #682).
- **Two projects run side by side.** The gateway, runner and embedded PostgreSQL ports follow the
  web port, and `aw dev` reports every busy port at once with the setting that moves it
  (#660, #664, #674).
- **Rate a run from the CLI.** `aw runs rate <id> --up|--down [--comment <text>]` and
  `client.runs.rate()` (#665, #671).
- **Evaluate any version.** `aw eval` runs each case on a session pinned to the requested version,
  whatever `local` points at; `evaluation_version_not_local` is removed (#618, #669).
- **Promotion gate.** A project policy can set `promotion.minEvalScore`; `aw promote` refuses a
  version that has no evaluation or scored below the bar (#619).
- **`@indx-workspace/react`, for the first time.** `<Chat/>` with replaceable parts, the headless
  `useConversation()`, and `baseUrl` to talk to an Agent Workspace on another origin (#623, #673,
  #679).
- **Cross-origin embedding.** The visitor run routes answer CORS preflights for the surface's
  allowed origins, so `<Chat baseUrl>` works from a customer's site (#680, #681, #686).
- **Visitor token proof.** The visitor-token verification has a Lean proof (#677).
- **Version history in the web app.** An agent's Versions tab lists its versions with the score
  of each version's newest evaluation, and `GET /api/agents/:id/versions` returns the same data in
  `evaluations` (#712, #714, #716, #718). The refusal messages are also available in Japanese, and
  `Accept-Language` q-values are honoured.
- **Talk to an agent from the terminal.** `aw chat [agent] -p <text>` sends one prompt; on a
  terminal without `-p` it opens an interactive loop that streams the answer, prints each tool
  call as one line, and interrupts a turn on Ctrl-C. `--agent-version <n>` or `--env
  local|production` runs the conversation on a chosen version (#706, #720, #725).
- **Tools as code.** `defineTool({ name, description, input, output?, run, limits? })` in
  `@indx-workspace/sdk/define` declares a code tool; `run` is a project-relative path that is
  never imported by the declaration (#709).
- **Skills are project files.** `aw check` reads `skills/<name>/` folders and refuses a
  `skill('x')` that names neither a folder nor a workspace skill; the project plan lists each skill
  as create, update or unchanged (#713).
- **`npm create` never stops.** With no terminal and no `--yes` it takes the recommended answers
  and says so on stderr instead of refusing. Every setup question has a flag (`--theme`,
  `--agent`, `--provider`, …), and `aw init` takes the same flags; the generated `package.json`
  carries npm's `allowScripts` (#708, #722).
- **A first evaluation in a minute.** New projects get `evals/<agent>.yaml` with a few cases;
  `aw eval` with no arguments runs every agent that has such a file on the `local` draft, and
  `aw eval add "<input>" [--agent <name>] [--expect-contains <text>] [--expect-tool <name>]`
  appends a case to the file locally (#711, #719).
- **A calmer `aw dev`.** One ready screen replaces the start-up output, the runtime's own log goes
  to `.aw/logs/runtime.log`, an unpinned busy port set moves together to the next free one, and the
  local runtime no longer seeds an extra `General` agent (#715).
- **Security.** `pi-coding-agent` moves to 1.0.2 and `@anthropic-ai/sdk` is pinned at 0.129.0 in
  `@indx-workspace/embedded`, which clears the HIGH advisory (#675, #668).

## What does not work yet

- **No upgrade path from 0.2.1.** A 0.2.1 project is not migrated; generate a new project.
- **Every recorded time uses a stub model.** The nightly live-model journey is separate (#609).
- **Signed images** are not in this release.
- **`@indx-workspace/react` has never been published.** Before `packages-v0.4.0` is tagged, the Owner publishes a placeholder of it by hand and configures its trusted publisher ([release procedure](../README.md#npm-packages), ADR-0082 D5); until then the publish job stops on it.
- **No npm provenance** while the repository is internal (ADR-0082 D5).
- The list in [0.3.0's "Left for later"](0.3.0.md#left-for-later) still stands.

## Compatibility

`CONTRACTS_VERSION` moves to 0.4.0, a minor: a 0.4 control plane still serves 0.3 clients (one minor
back). A 0.3 client refuses the served shapes that only 0.4 has (`bar` on a pointer move,
`model_connection_failed`, a policy that carries `promotion`) with `ContractViolationError`, and a
0.3 server refuses a policy that carries `promotion` at start-up. See the contracts changelog.

`StartRunRequestSchema` gains an optional `version` (#725), and a 0.3.0 server does not read it: its
start-run route rejects any key other than `prompt`, `sessionId`, `modelConnectionId` and `model`
(`parseStartRunBody`, `apps/web/server/runs/api.ts:115-121` at `packages-v0.3.0`). A 0.4 SDK or
`aw chat --agent-version`/`--env production` that sends `version` to a 0.3.0 server is refused with
`400 invalid_body` (`unknown field "version" in the request body`); omit it against 0.3 servers.
`aw chat` without those flags sends no `version` and works against both. The setup questions in
`@indx-workspace/contracts/setup` gain a `flag` (#708) and `create` and `aw init` read it locally;
it is not on any HTTP route.
