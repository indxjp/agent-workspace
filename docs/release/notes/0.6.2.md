# `@indx-workspace` packages 0.6.2 release notes

Release status: **published on npm on 2026-10-12.** These notes describe the lock-step 0.6.2 release of the eight
npm packages (`@indx-workspace/contracts`, `platforms`, `sdk`, `react`, `aw`, `cli`, `embedded`,
`create`), cut from a `packages-v0.6.2` tag by `.github/workflows/publish-packages.yml` once the
platform images `images-v0.6.2` are public ([release procedure](../README.md#npm-packages)).

This page says what landed since `packages-v0.6.1`; each package's `CHANGELOG.md` lists the detail
under its 0.6.2 heading. `@indx-workspace/platforms` is published for the first time in this release.

It is a patch release: the contract changes are additions (public-surface policy), so
`@indx-workspace/sdk@0.6.x` and `@indx-workspace/aw@0.6.x` both speak contracts 0.6. One exception
to note: `A2A_PROTOCOL_VERSION` is now `0.3.0` instead of `0.3`, and `A2aAgentCardSchema` is strict,
so parsing a card served by an older server with it refuses `0.3`.

## Fixes

- **Uploaded files create their folder.** Uploading a file now creates its parent folders, so a
  `files('<folder>')` grant resolves once a file is uploaded into it, and a migration adds the
  missing folders for files uploaded earlier. `aw files mkdir` on a folder that already exists says
  so and exits 0 (#899).
- **Push refuses code tools the sandbox cannot restrict.** A code tool that declares
  `allowedDomains` on a deployment whose tool sandbox cannot enforce them (E2B, or docker without the
  egress proxy) is refused at `aw push`, and when a version pointer moves, with
  `422 network_policy_unsupported` naming each tool. Before, the push succeeded and every run then
  failed with `503 tool_sandbox_unavailable` (#1018).
- **`aw push` keeps the agent's runtime profile.** First-run setup now marks the profile it creates
  as the workspace default, so a pushed agent no longer ends up with no runtime profile
  (`agent_runtime_profile_missing`) (#1057).
- **`aw eval` runs as an evaluation run.** Every evals file runs as an evaluation run advanced step
  by step, instead of one synchronous request for 20 cases or fewer. Each case gets its own
  deadline, so the last cases of a slow agent no longer end `deadline_exceeded`, and a proxy that
  drops a long request no longer fails the file; a dropped advance is retried. The output and
  `--json` shape are unchanged (#1057, #1062).
- **Gallery agents declare tool approval in code.** `defineAgent` takes
  `engine: { id: 'claude-agent-sdk', autoApprove: [...] }`, stored with the version so `aw push`
  saves it. The gallery agents that run skill scripts declare `Bash` (and cad-drafting `Write`), so an
  unattended run no longer stops at an approval prompt it cannot answer (#1062).
- **A run's E2B tool sandboxes are killed when it ends.** On the `external` (E2B) driver, a run that
  succeeds, fails, is cancelled or hits its deadline now releases its agent-runtime and tool
  sandboxes, instead of leaving them alive until they time out and exhausting the provider's
  sandbox limit (#1066).
- `aw eval run` prints the stored error of a failed case's run under its line (#981). A run whose
  request cannot be prepared fails with `run_preparation_failed`, naming the failing step (#988).
  The OAuth sign-in returns to the authorize page through the workspace picker (#1065).

## What changed since 0.6.1

- **Portable agents and agent platforms** (ADR-0133). The new `@indx-workspace/platforms` package
  compiles a project's agents to Claude Managed Agents, Copilot Studio, Microsoft 365 declarative
  agents, Microsoft Foundry, Gemini Enterprise and AWS AgentCore, and ejects them to the Claude Agent
  SDK, Mastra or the OpenAI Agents SDK, with a per-field verdict for what each platform keeps or
  drops. Most targets also import back. `aw platforms list|export|import|doctor|publish` drives it:
  `publish` shows the vendor tool's own plan and applies only with `--yes`. The console has a
  Platforms tab on the agent page, and `docs/platform-matrix.md` lists every target.
- **Subagents, description and knowledge.** `defineAgent` takes `description`, `subagents` and
  `knowledge`. The Claude Agent SDK, Mastra and OpenAI Agents engines run a version's subagents;
  pi refuses them, nested subagents are refused, and `aw push` saves agents in subagent order.
- **Subagents on Mastra and OpenAI Agents.** Mastra runs each subagent as a sub-agent with its own
  workspace and tool set; OpenAI Agents runs it as a nested run exposed as a tool, not a handoff.
  Both count a subagent's usage against `maxBudget` without counting it as one of the run's turns,
  and refuse by name a subagent on another model when a budget cap is set, because the cap is
  priced with the parent's model (#1068).
- **Setup asks which agent platforms to publish to.** `npm create`, `aw init` and the browser setup
  ask a twelfth question, `--platform <a>[,<b>…]` (asked last, default `none`). Each chosen platform
  is written as `platforms: {<id>: {enabled: true}}` in `agent-workspace.yaml`, with a "Publish to
  other agent platforms" README section and an "Other agent platforms" AGENTS.md section. With
  `none` every file is unchanged. An unknown platform id is a usage error (#1069).
- **Endpoint clients** (ADR-0134). Endpoint clients with endpoint-scoped API keys, an OAuth 2.1
  authorization server for them, and a project's code tools served at one public MCP endpoint.
  `aw endpoint-clients` manages them, including `secret rotate`.
- **A2A** (ADR-0135). Published agents are served over A2A v0.3 JSON-RPC. `aw deploy` and
  `agent-workspace render` carry `AW_PUBLIC_URL` (written as its origin) into Compose, Cloud Run,
  Azure Container Apps, Helm, Vercel and Cloudflare, so a deployment can serve agent cards.
