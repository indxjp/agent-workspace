# Agent Workspace 0.1.0 release notes

Release status: **blocked until the residual-risk list is signed**. D-10 forbids the `v0.1.0` tag
while [`docs/release/security-review-0.1.0.md`](../security-review-0.1.0.md) has empty `Accepted-by` fields. These
notes describe the release candidate artifacts; they do not announce a release.

## What the candidate contains

- A self-hosted control plane, private model gateway, runner, PostgreSQL persistence, projects and
  sharing, local/Docker/Kubernetes runtime support, OIDC, audit/telemetry, packaging, and first-run
  setup delivered by Waves 0-7.
- A spec-derived eleven-step E2E harness with explicit `passed`, `failed`, and narrowly-scoped
  `credential-bound` results.
- Evidence-backed provider and runtime matrices. Their current claims and evidence basis are the
  generated [`provider matrix`](../../compatibility/providers.md) and
  [`runtime matrix`](../../runtime-driver-matrix.md), not a second list in these notes.
- A reproducible security review and a ten-step non-engineer walkthrough instrument.

## Tested scope and distribution

Under D-03, Anthropic and Azure OpenAI are the tested provider scope. OpenAI and
OpenAI-compatible ship untested and are marked out of the tested 0.1.0 scope. No live provider
credential was available for the release-candidate run, so recorded fixtures—not a claimed live
answer—back the positive provider marks.

Under D-05, **no published container image is part of this candidate**. Build instructions for the
single-VM Docker Compose path and the Kubernetes path are included in the repository.

## Known release blockers

- D-10: the three residual risks in the security review are unsigned.
- The full live-model E2E path remains credential-bound in this deployment.
- The required Files, Skills, and Connectors screens were not delivered by Wave 2c.
- Runnable share links exist although D-06 defaults 0.1.0 to definition sharing only.
- The section 55 walkthrough has not been performed or independently approved by a non-engineer.

No `v0.1.0` tag should be created until the Owner signs the residual risks and the release manifest's
`Met: no` causes are resolved or explicitly superseded by recorded decisions.
