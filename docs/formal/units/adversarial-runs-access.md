# Adversarial run access

## Model

`Theorems/Adversarial/AdversarialRunsAccess.lean` states the attacker-controlled credential kind, route, path and foreign identifiers, with the principal and ownership fact resolved by the server. It imports the integrated run transition, tenancy, and run-token models. Sixteen T3 theorems cover foreign-state preservation, foreign and other-owner list postconditions, browser run and session scope grammar, bounded ownership, named-route denial, Builder/Viewer revoke denial, the Viewer agent-run grant boundary, and gateway run-token mismatch, expiry and revocation. The finite search spans 50 attempts across Owner, Builder, Viewer, browser run and browser session credentials. `Vectors/AdversarialRunsAccess.lean` supplies 25 route, tenant, ownership and browser-scope scenarios.

## Evidence

The real `installRunApi` / `InMemoryRunStore` replay in `apps/web/formal/adversarial-runs-access.test.ts` exercises foreign read, list, stream, interrupt, revoke, agent start, and session continuation. It checks the same-ID absent/foreign response, unchanged foreign state, other-owner Builder/Viewer denial, and browser-token scope on read, stream, list, start, interrupt, and revoke. One case folds IDs in the store adapter to mimic PostgreSQL UUID lookup while checking the real handler's tenant guard. The real `/api/tokens` route refuses a nominal browser-token principal without invoking issuance. A separate real proxy/credential-parser test reproduces D1 suspicious point 20. Family-only generation produced 25 vectors; 33/33 narrow Vitest cases pass. Named Lean build, axiom audit, import-direction audit, and 546-entry citation validation pass.

Six author definition mutations were killed by narrow Lean builds and restored byte-for-byte: dropping workspace from `found`, creating a run in a foreign workspace, dropping workspace from interrupt selection, widening list grants, ignoring session scope, and ignoring gateway expected-run mismatch. The first five restored `Behaviour/Runs.lean` to SHA-256 `34055719e7e297a65bb6161feced0ade693d7d193d763822daaf1cde932a86c5`; the sixth restored `Authz/RunToken.lean` to `e375f3ca10823e973bf5648ec4647665bcc32a23613b82674aad272a61930846`. The independent frozen-source pass ran ten fresh mutations: nine failed the named build and one survived, admission of `agents.write` for session browser scope. The strengthened `session_browser_scope_grammar` theorem now kills that exact mutation at its own statement. `Authz/TokenScope.lean` was restored to SHA-256 `2d21098d123c6053fcafd0f106fe7266375fd579e52ea01e33384a348cc21040`, and the final clean narrow build passed.

## Findings and gaps

No new security defect is confirmed by this unit's completed replays. **Correctness finding (D1 point 20):** `readBearerBrowserTokenAttempt` accepted a lowercase bearer scheme while the proxy rejected it. PR #283 aligned the proxy with the parser; the real proxy replay now accepts both canonical and lowercase bearer schemes.

The named-route theorem guarantees no success for an absent scoped run. Exact 404 concealment is conditional: the revoke role gate returns 403 for Builder/Viewer before lookup, and invalid or unauthenticated requests may return 400/401. The real replay compares absent and foreign responses under identical preconditions; it does not claim unconditional 404.

The run-route model carries `ownerFilter`, not returned list rows; row filtering is checked against the real store. `Behaviour.Request.ownership` is a server-supplied fact; `bound_other_member_is_not_own` requires `ownershipBound`, whose connection to the production `ownsRun` callback is checked by the real replay but not derived inside Lean. The Viewer agent-run theorem checks the RBAC boundary under two server-established grant facts; this unit does not replay the production `agent_grants` lookup. The app replay injects a resolved browser principal, so it checks route scope rather than the PostgreSQL credential resolver's revocation and expiry; `apps/web/formal/authz-run-token.test.ts` covers that resolver when its database prerequisite is available. Gateway `authenticateGatewayRequest` is internal to `packages/gateway`, so this app unit does not directly import it across the package boundary; `packages/gateway/src/auth.test.ts` is the real gateway replay. An actual PostgreSQL UUID case-variant replay and the production composition of a foreign session/agent remain to be checked through their service-backed harness before claiming the full A1 result.
