## Modelling decisions

- **The query's role is a string.** `decide()` re-parses `query.role` at run time, so `Query.role`
  is `RoleInput := String` and refusing an unknown spelling is part of the model.
- **`decideAuth`, not `decide`**: `decide` is Lean's `Decidable.decide`.
- **Strings are `List Char`.** `classifyPath` and `parsePath` run over `String.toList` with
  structural helpers, so concrete paths are decided by `decide` in the kernel. `toLowerCase()` is
  ASCII lower-casing: it is used only for the `/api` prefix test, and no non-ASCII code point
  lower-cases to exactly `a`, `p`, `i` or `/` (U+0130 becomes `i` + U+0307). The vectors include
  `/APİ/x`.
- **`POLICY` is transcribed literally** (fallback plus override list, same constants). The 104 cell
  theorems pin it against a third, hand-typed reading in the macro invocations and against
  `documentedGrants`. The comparison is on **reachable** operations only: `run` is reachable only
  for `agents`, `sessions` and `runs`, where a run sub-resource exists (`opReachable`).
- **Workspace wording is interpreted.** The §3.3 phrase "read any membership" is represented as
  `read: own`: a caller reads workspaces through its own membership. The source does not spell out
  that grant value, so the agreement tag on these cells depends on this interpretation.
- **Facts do not depend on ownership.** The vectors store one facts/code/reason per query and an
  effect per ownership answer. The TypeScript side checks all five against the shared value.
- **Revocation is a separate capability.** `decideAuth` checks it before the ordinary operation
  table. `decideOrdinary` isolates the unchanged policy branch for the table proofs; the new
  revocation theorem covers both route shapes and every ownership answer.

## Attacker model (`decide()`'s share)

The attacker chooses the method, every byte of the pathname, and the id of a browser-token scope.
It holds one role and reports whatever ownership fact a handler would pass. It must not: reach a
cell outside its scope's grammar; reach another run with a run scope; list runs or mint a token
with a scope; disguise an `/api` path as public by case, backslash, percent-encoding, overlong
UTF-8 or dot segments; reach a resource or sub-resource nobody classified; or reach Owner-only
resources with a narrower role. The scope, route and role theorems quantify over every query.
For the decoder, `decode_step_is_well_formed` proves that one successful decoding step reads a
plain character or a well-formed UTF-8 escape group (ASCII lead, or a `C2`…`F4` lead with exactly
its announced continuation bytes, encoding a shortest-form non-surrogate scalar value, by
`utf8_accepts_only_shortest_scalar_values`), and that the remaining input decodes. The theorem does
not separately state a whole-input induction. The byte-level rejections are
exhaustive over one byte (`uri_decode_rejects_bad_lead_and_continuation_bytes`: every non-continuation
byte after a 2-, 3- and 4-byte lead, every lone continuation byte, every lead `F5`…`FF`). The
prefix-rule theorems about whole paths (`encoded_traversal_stays_protected`) are finite example lists,
backed by the universal `api_variants_are_protected` and `public_needs_the_raw_path_under_p`. No
counterexample holds against today's code.

## Gaps

- Handler-side rules (AZ-16 … AZ-31) belong to `Behaviour/Runs`, `Authz/Tenancy` and
  `Authz/RunToken`. This unit models only `decide()` and the one handler gate point 10 needs.
- `classifyPath`'s non-string input branch is not modelled, because `decide()` always passes a
  string. JavaScript lone surrogates are not representable. `decodeURIComponent` refuses them.
- The `because` sentences are checked by keyword, not verbatim.
