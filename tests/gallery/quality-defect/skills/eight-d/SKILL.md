# 8D レポート下書きの書き方

下書きは DR（デザインレビュー）で有識者が確認する前提の**たたき台**です。断定より根拠を優先します。

## 書式

見出しは次の8つを、この順で、1回ずつ書く（`##` 見出し、`D` と数字は半角）。

```md
# 8Dレポート（下書き）: <品番> <現象> <ロット>

## D1 チーム編成

## D2 問題の記述

## D3 暫定対策

## D4 根本原因（なぜなぜ分析）

## D5 恒久対策の選定

## D6 恒久対策の実施と効果確認

## D7 再発防止（水平展開・FMEA反映）

## D8 完了と振り返り
```

- D2 は 5W1H（何が・どこで・いつ・どれだけ）で、入力された現象・品番・ロット・工程・発生数をそのまま書く。
- D4 には次の行を必ず書く。
  - `原因区分: <区分>` … 過去トラの `causeCode` の語彙（例: 金型摩耗、段取り条件誤り）から選ぶ。
  - `4M集計: …` … `causeStats` が返した `line` を**一字一句そのまま**写す。自分で数えない。
  - `- なぜ1: …` から `- なぜN: …` まで、**3段以上**。番号は 1 から連番。
  - `- 根本原因: …`
- D4 の各行（なぜ・根本原因・箇条書き）の末尾に、根拠にした過去トラを〔過去トラ Q-1003〕の形で付ける。
  複数なら〔過去トラ Q-1003、Q-1011〕。番号は `searchDefects` / `getDefect` が返した `citation` を写す。
- 過去トラで裏付けられない推定は書かないか、D2 の「未確認事項」に回す。D4 に出典のない行を書かない。
- 同じ原因区分の過去トラがあり、その `recurred`（再発有無）が「有」なら、D7 の冒頭に
  `再発: 〔過去トラ Q-xxxx〕と同一原因（<原因区分>）` と書き、前回の対策がなぜ効かなかったかを書く。
- D5〜D7 は過去トラの対策・水平展開を参考にするときも、必ず引用を付ける。FMEA の該当行（例: P-03-01）があれば
  D7 で見直し案を書く。

## D8 は DR の承認で登録する

下書きを書いたら、回答の前に `qms` の `createCase` を呼ぶ。引数は `body` で、その中身は `report`（8D 全文）、`title`（現象）、
`partNo`・`process`・`lot`・`count`、`cause`・`causeCode`・`fourM`、`whys`（D4 のなぜ〜根本原因）、
`countermeasure`（D5）、`horizontalDeployment`（D7）。この呼び出しは DR が承認するまで実行されず、
承認されて初めて過去トラ（Q-xxxx）として登録される。

- 拒否（`rejected: <指摘>`）されたら、指摘を反映した下書き全文で `createCase` をもう一度呼ぶ。
- 承認（`approved`）されたら、同じ引数でもう一度呼び、返った登録番号（`qNo`）を確かめて下書きを回答する。
- 類似の過去トラがなく 8D を書かないときは、登録も求めない。

完成例は `examples/8d-sample.md`。

## 類似の過去トラがないとき

`searchDefects` が言い換え3回でも `noMatch: true` なら、他のツールを呼ばず、8D・見出し・〔過去トラ〕の引用・
参考の骨子を書かずに、返った `message`（次の文）だけをそのまま貼って答える:
「類似する過去トラは見つかりませんでした。品質保証課で新規不具合として登録してください。」

## 手動でのチェック（任意）

エージェントの実行では行わない。バックエンドが同じパーサ（`eightd.mjs`）で下書きを検査する。
手元で確かめるときは、`run_skill_script` ツールで下書き全文を `--text` の引数として渡す（標準入力もシェルもない）。
1つの引数は 8 KiB（日本語でおよそ 2,700 字）まで。超える場合は節ごとに分けて確認する。

```json
{ "skill": "eight-d", "script": "eightd.mjs", "args": ["--text", "（下書き全文）"] }
```

出力 JSON の `valid` が `false` なら、`issues` の各項目（`missing_section`、`shallow_whys`、
`uncited_claim` など）が、DR で確認されるべき点になる。

## してはいけないこと

- 件数・割合を頭の中で数えない。4M の件数は `causeStats` の出力だけを使う。
- 検索で返っていない不具合番号を書かない（バックエンドが照合し、DR で差し戻される）。
