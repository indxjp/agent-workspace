# 議事録の書き方（社内標準）

文字起こし（Teams / Zoom の話者つきテキスト）から、次の書式で議事録の**下書き**を作る。
見出しの名前と順番は変えない。後工程のシステムがこの見出しと表を読む。

```md
# 議事録

- 会議名: 第2工場 生産会議（10月度第1回）
- 日時: 2026-10-02（金）10:00〜10:45
- 場所: 第2工場 2F 会議室B（Teams 併用）
- 出席者: 佐藤 健一 部長、鈴木 一郎 課長、伊藤 美咲 さん、株式会社ミナト金型 木村 浩二 様
- 記録: 議事録エージェント（下書き・未承認）

## 議題

1. …

## 決定事項

1. …（誰が決めたか分かるときは「佐藤部長決定」と添える）

## 継続課題

- …（次回に持ち越した論点。担当や期限が決まっていなくてよい）

## アクション項目

| No. | 内容                             | 担当      | 期限       | 根拠（発言）                            |
| --- | -------------------------------- | --------- | ---------- | --------------------------------------- |
| 1   | ライン3 段取り替え試行計画の作成 | 鈴木 一郎 | 2026-10-09 | [00:03:24] 来週金曜までに出します       |
| 2   | 来客対応手順の見直し             | 担当未定  | 2026-11-10 | [00:05:36] 担当は次回までに決めましょう |
```

## 出席者と敬称

- 社内は「氏名 役職」（役職が敬称を兼ねる）。役職のない人は「氏名 さん」。
- 社外は「会社名 氏名 様」。
- 氏名・部署・役職は `list_members` の結果に合わせる。文字起こしの表記（「鈴木さん」「品証さん」）を
  そのまま使わない。

## アクション項目のルール

1. **担当を作らない。** 発言の中で本人が引き受けたか、指名されて了承したときだけ担当を書く。
   「誰かが」「営業さんの中で」「次回決めましょう」は **担当未定** と書く。出席者の中で一番それらしい人を
   推測して入れない。
2. 担当欄は `list_members` の氏名（敬称なし）。社外の人が引き受けたときは「株式会社〇〇 氏名 様」と書く
   （タスクトラッカーには登録できないので、承認時に社内の窓口を決めてもらう）。
3. 期限は **YYYY-MM-DD**。相対表現は必ずスクリプトで直す。頭の中で計算しない。

   `run_skill_script` ツールで呼ぶ（シェルはない）:

   ```json
   {
     "skill": "gijiroku-format",
     "script": "dates.mjs",
     "args": ["<会議日 YYYY-MM-DD>", "来週金曜", "月末", "3営業日後"]
   }
   ```

   - 基準日は会議の日（文字起こしの「日時」）。今日の日付ではない。
   - 週は月曜始まり。「来週金曜」は会議の翌週の金曜。「週明け」は翌週の月曜。
   - 「月末」は暦の末日（土日でもそのまま）。「N営業日後」は土日を飛ばす（祝日は考慮しない）。
   - スクリプトが `null` を返した表現（「なるべく早く」「近いうちに」）は **期限未定** と書く。

4. 「根拠（発言）」には、その項目の担当と期限が読み取れる発言を `[時刻] 発言の要約` で書く。
5. 依頼が構造化出力（`minutes` と `actionItems`）を求めているときは、`minutes` に議事録の全文を、`actionItems` に表と同じ内容を入れる。`assignee` と `due` の値は表と一字一句同じにする。

## してはいけないこと

- 下書きの段階で `createTask` を呼ばない。登録は、人が確認・承認した項目だけを、項目ごとの次の依頼で行う。
- 決定していないこと（「試してみたい」「検討します」）を決定事項に書かない。継続課題に書く。
- 数値（不良率・dB・日数）を言い換えない。発言のまま書く。
