# STD-01 テスト設計の決まり（開発部）

テスト設計書は、仕様書から作るテストケースの一覧と、テストコードの下書きをまとめた文書。担当者が見直してから使う。

## テストケース

- ID は `TC-01` から順に振る。一つのケースは、一つの入力と一つの期待結果。
- 各ケースに、要件（REQ-xx）、観点（正常・境界・異常・回帰のどれか）、入力、期待結果、根拠を書く。
- 期待結果は、仕様書の計算例（EX-xx）に書かれた値だけを使う。計算例にない入力のケースは、期待結果を「要確認」とし、確認事項に挙げる。期待結果を自分で計算しない。
- 境界のある要件（端数、上限）は、境界の値のケースを必ず入れる。
- 不具合一覧（BUG-xx）の不具合ごとに、同じ入力の回帰のケースを一つ入れる。

## テストコードの下書き

- Vitest の形で書く。`describe` は関数名、`it` は一つのケースに一つで、名前は TC の ID と観点。
- エラーのケースは `expect(() => ...).toThrow(...)` で、エラーのコードを確かめる。
- 下書きは実行していない。実行して確かめるのは担当者。

## 確認事項

- 仕様書で決まっていないこと（別紙が未着の要件など）は、テストケースにせず、確認事項に挙げる。
