# GUIDE-01 リリースノートの書き方

ヤマガラ勤怠の利用者（従業員・勤怠管理者・連携の開発者）に向けて、リリースごとに一つ書く。

## 1 グループと順番

PR のラベルで次のグループに分け、この順に並べる。項目のないグループは書かない。

| ラベル   | グループ                     |
| -------- | ---------------------------- |
| breaking | 互換性に関する重要なお知らせ |
| security | セキュリティ                 |
| feature  | 新機能                       |
| bug      | 不具合の修正                 |

- 1.1 ラベル `internal` と `docs` の PR は利用者に影響しないため載せない。
- 1.2 一つの PR に複数のラベルがあるときは、表の上にあるグループに入れる。

## 2 一項目の書き方

- 2.1 利用者から見て何が変わるかを一文で書き、最後に PR 番号を（#481）のように添える。
- 2.2 社内の担当者名・ブランチ名・開発用語は書かない。
- 2.3 互換性に関する項目には、利用者がすべきこと（移行先など）を書く。
- 2.4 PR に書かれていない効果（速くなった、など）や今後の予定は書かない。

## 3 見出し

- 3.1 文書の見出しは「ヤマガラ勤怠 <バージョン> リリースノート」とする。
- 3.2 リリース日は、決まっていれば見出しの下に書く。決まっていなければ空けておく。
