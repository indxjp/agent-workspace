# Claude Development Instructions

Read and follow [AGENTS.md](AGENTS.md), [ENGINEERING_GUIDELINES.md](ENGINEERING_GUIDELINES.md), and
[docs/architecture.md](docs/architecture.md) before editing this repository. Before touching
`packages/contracts`, `packages/sdk`, `packages/aw` or an SDK migration unit, also read the
one-page [SDK structure map](docs/sdk/07-structure-map.md). If these instructions conflict, the
engineering guidelines and narrower directory-specific instructions win.

[llms.txt](llms.txt) is the reading index for this repository: the rules above, the product and
design documents, and every page of the developer docs site (`docs/sdk/site/`), in reading order.
Use it to find the document that answers a question before searching the tree. It is generated by
`pnpm docs:generate` and checked by `pnpm docs:check`; when you add or rename a document it should
list, regenerate it rather than editing it.

For every task:

1. Inspect the complete change boundary and preserve unrelated user work.
2. State a small, risk-ranked plan before broad refactoring.
3. Keep contracts, domain decisions, and infrastructure adapters separated by the documented
   dependency direction.
4. Validate runtime inputs, use strict readable TypeScript, and return only safe typed API errors.
5. Add focused regression tests and run the relevant checks while iterating.
6. Finish with `pnpm check:fast`, `pnpm test`, and `pnpm build`, reporting any check that could not
   run instead of silently skipping it.

Do not weaken a quality gate, broaden an ignore, add a suppression, or create a speculative layer to
make a change pass. Fix the underlying issue or document a narrow, reviewable exception in the place
the repository standard requires.
