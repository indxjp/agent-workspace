Maintenance, operations, contact-centre back office, internal help desk

Manual search agent

A field engineer asks 「油圧ユニットの定期点検の周期は？」 in the portal's side panel. The agent searches the manuals with the platform's search_files, narrowed to the manuals that person may read, rephrases when the first search misses, opens the page, and answers with the clause and its page; when nothing in the manuals answers the question, it says so instead of guessing.

benchmark 100/100Read the tutorial →
import { builtinSkill, defineAgent, files, skill } from '@indx-workspace/sdk/define';

export default defineAgent({
  name: 'manual-search',
  instructions: { file: './manual-search.md' },
  model: 'default',
  // A run is unattended: without autoApprove the SDK stops the tools' calls on an approval prompt.
  engine: {
    id: 'claude-agent-sdk',
    autoApprove: ['mcp__agent-workspace__run_skill_script', 'mcp__agent-workspace__search_files'],
  },
  // Read-only by construction: it searches the manuals with the platform's `search_files` and
  // reads the PDF through office-reader, nothing else. The portal narrows each run to the manuals
  // the signed-in person may read (`runs.start({ fileScope })`). `runCommands` is what offers
  // `run_skill_script`; no write, no network.
  permissions: { readFiles: true, runCommands: true },
  skills: [builtinSkill('office-reader'), skill('cite-answer')],
  files: [files('manuals', 'read')],
  limits: { maxTurns: 12, maxBudgetUsd: 0.5 },

export async function askManual(aw, agentId, question, subject, sessionId?) {
  const fileScope = fileScopeFor(subject);                      // the manuals data/access.json lets them read
  if (fileScope.length === 0) throw new NoManualAccess(subject); // no run at all
  const reading = await runAndRead(aw, agentId, { prompt: question, subject, fileScope, sessionId: sessionId ?? null }, ManualAnswerSchema);
  const found = new Set(
    reading.toolCalls
      .filter((call) => toolIs(call.name, 'search_files') && !call.isError)
      .flatMap((call) => foundIn(call.output ?? '')),
  );
  const { answer, citations } = reading.output;                  // typed, not parsed
  const unverified = citations.filter((citation) => !found.has(keyOf(citation.source, citation.page)));
  return { answer, citations, unverified,
           grounded: citations.length > 0 && unverified.length === 0, … };
}

What the tutorial says it does not do yet
  • A run's fileScope can only narrow the agent's file grants; a scope that widens them fails the run with 403 run_file_scope_not_granted.
  • Who may read which manual is your portal's table, not the platform's: the backend computes the scope and refuses a person with none before any run.
  • A search_files hit names a path and a page; checking that each citation was returned in the run is the backend's job.
Mechanical and electrical design, production engineering

CAD drawing agent

A designer types the requirements for a new part; the agent searches past drawings with the platform's search_files, narrowed to the drawing series that designer may use, by title block and outline size, proposes a change set to the closest drawing that the designer approves or sends back, and drafts a new DXF from it, marked 未検図 (not yet checked). It never invents a dimension.

export function draft(baseText, changes) {
  const base = summarise(baseText);
  const problems = [];
  // … drawingNo must be new, width and height positive …
  if (!base.rectangular) {
    problems.push(`${base.drawingNo} の外形は矩形ではありません。伸縮すると指示のない寸法が変わるため、手で作図してください`);
  }
  const holes = changes.holes ?? base.holes;
  if (problems.length === 0) problems.push(...holeProblems(changes.width, changes.height, holes));
  if (problems.length > 0) throw new DraftRefused(problems);

  // entity, and rewrite the title block: 図番, 作成, 検図 未, 状態 未検図, 派生元 <base>.
}

Requesting departments; approvers in planning, finance and legal; bank credit review

Ringi review agent

When a department files a ringi in the existing workflow system, your backend starts the agent, which checks it against the authority matrix, the ringi rules and past precedents it finds with the platform's search_files, narrowed to the departments the filer may read, and writes a review sheet with a clause for every finding. The agent never approves.

export async function startReview(ringi: RingiSubmission, deps: ReviewDependencies): Promise<string> {
  const fileScope = fileScopeFor(ringi.submittedBy, deps.access);
  const { run } = await deps.aw.runs.start(deps.agentId, {
    prompt: RINGI_TRIGGER.prompt.replace('{{body}}', () => JSON.stringify(ringi)),
    subject: ringi.submittedBy,
    fileScope,
    idempotencyKey: `${ringi.ringiId}@${ringi.revision}`, // a retried filing starts no second run
    outputSchema: ReviewSheetSchema, // the run answers in the review sheet
    ...(ringi.quotes === undefined ? {} : { attachments: ringi.quotes.map(({ fileId }) => ({ fileId })) }), // the agent reads each quote
  });
  return run.id;
}

// Read the settled run and re-check route, missing fields and citations. The agent posts the comment itself, once a person approves the call.
const { review, comment } = await reviewRun(runId, ringi, deps);

## 使ってはいけない表現

- 返金・補償・値引きを約束する表現: 「返金いたします」「返金します」「全額お返しします」「補償いたします」
  「無料にいたします」。返金の可否と金額は担当者が判断する。
- 個人情報の復唱: 電話番号、住所、メールアドレスを書かない。お客様が書いたものも繰り返さない。

export async function chat(aw, agentId, input: ChatInput): Promise<ChatReply> {
  const reading = await runAndRead(aw, agentId, {
    prompt: message,                         // the customer's words, nothing else
    subject: input.customerId,               // who is signed in, signed by the platform for the CRM server
    sessionId: input.sessionId ?? null,      // same session for the whole conversation
  });

  // Defence in depth: the server masks, but the model also sees what the customer typed.
  const pii = findPii(reading.answer, { allow: PUBLIC_NUMBERS });
  const refundPromise = REFUND_PROMISE.test(reading.answer);
  if (pii.length > 0 || refundPromise) {
    return { …, text: WITHHELD_ANSWER, handoff: true, reason: 'guard', withheld: { pii, refundPromise } };
  }

  const reason = handoffReason(reading.answer);   // 「担当者におつなぎします」 + 〔引継ぎ: …〕
  return { …, text: withoutTag(reading.answer), handoff: reason !== null, reason, withheld: null };
}

From tutorial to agent

Start from the closest example, then make it yours.

The docs suggest finding the row closest to your use case and reading its tutorial. From there the path to production is five steps, all in the aw CLI.

  1. Pick the closest tutorial. Its "Where the SDK stands" section says what works today and what you would write yourself.
  2. Run it locally. aw dev runs the project on one Node process with embedded PostgreSQL, no Docker, and pushes agents/ and surfaces/ on every save.
  3. Write the skill and assign the files. A SKILL.md under skills/<name>/, imported with aw skills import; documents assigned read-only or read-write.
  4. Write down what "good" means. Cases in evals/<agent>.yaml, run with aw eval; a thumbs-down becomes a case with aw eval add-case.
  5. Save a version and promote it. aw push --yes moves local; aw promote --yes moves production, gated on aw dev by minEvalScore if you set one. aw rollback moves it back.
$ npx aw dev
$ npx aw skills import ./release-notes
$ npx aw eval
$ npx aw push --yes
$ npx aw promote --yes
Node 24 or newer

aw eval exits 1 on any failed case, so the same command gates CI. Full reference: CLI commands · evaluations · code examples

Limits, stated up front

What these examples do not do yet.

Each tutorial is also a benchmark, and the docs publish its gaps beside it. Read these before you pick one.

⚠ No typed data back from a run.
The benchmark's "Struct" column is "not provided yet" for all ten tutorials: a backend gets text, not typed data, from a run today.
⚠ Public runnable agent shares are off.
The runnable share mode is refused (400 invalid_share). A share is a snapshot. For public visitors, publish a surface with allowedOrigins.
⚠ stdio connectors are stored but cannot run.
Use http or sse. Every connector in these examples is an MCP server you host.
⚠ Code tools run only in aw dev.
A version that uses a defineTool() tool cannot be promoted (422 code_tool_needs_host). Deploy with openapiTool() (read-only GET/HEAD) or an MCP server.
⚠ No webhooks yet.
Your backend polls or streams in-process. Pass runs.start an idempotencyKey (sent as the Idempotency-Key header) so a retried start returns the first run.
⚠ Other providers and managed clouds are not live-proven.
Non-Anthropic model adapters are fixture-verified; no managed-cloud sandbox driver has a live isolation proof.
