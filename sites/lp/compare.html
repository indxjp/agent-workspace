The alternatives are good. They answer a different question.

Managed agent clouds, agent deployment platforms and visual builders all run agents well. The question Agent Workspace answers is narrower: how do we run the Claude Agent SDK, unchanged, with the whole control plane inside our own infrastructure? This page shows where each option fits, with a source for every statement about another product.

When to choose what

Pick by the constraint you cannot move.

Choose Agent Workspace when

  • the agents are, or will be, built on the Claude Agent SDK
  • the control plane, data and sandboxes must stay in your account or data centre
  • admins need a browser UI and developers need TypeScript, CLI and CI
  • procurement may move you to Azure OpenAI or another cloud later
  • you want a plain Apache-2.0 licence and nothing proprietary to migrate off

Choose a managed agent cloud when

  • you would rather not operate anything at all
  • the vendor's region, data terms and retention fit your policy
  • you are already standardised on that cloud's identity and networking
  • you want the vendor's own long-running, managed sessions

Choose a visual builder when

  • the people building agents prefer a canvas to code
  • the agent is one step in a wider business automation or RAG app
  • their licence terms fit how you will deploy it

Build it in-house when

  • you have a platform team with time to own it for years
  • your requirements are unusual enough that no product fits
  • you accept that sandboxing, secrets, sessions and audit are now yours
Product by product

What each one is good at, and how it differs.

Strengths first. Each card cites the vendor pages it is based on.

Managed agent cloud · beta

Claude Managed Agents

Anthropic's pre-built agent harness running on managed infrastructure, for long-running and asynchronous work. Sandboxes can be Anthropic-managed or self-hosted.

Where it is strong

Managed, stateful long-running sessions with server-side history, built-in caching and compaction, and scheduled deployments, from the model vendor itself.

How Agent Workspace differs

Orchestration stays on Anthropic's side even with self-hosted sandboxes; Agent Workspace runs the whole control plane in your infrastructure and can use non-Claude models through its gateway.

not currently eligible for ZDR or HIPAA BAA

Managed agent cloud · AWS

Amazon Bedrock AgentCore

An AWS platform to build, connect and run agents built with any framework and any model, with runtime, memory, gateway, identity and observability services.

Where it is strong

A dedicated microVM per session, sessions of up to 8 hours (14 days on Instances), consumption pricing and built-in identity integration at AWS scale.

How Agent Workspace differs

AgentCore runs on AWS only. Agent Workspace runs on any cloud or none and adds a browser admin UI around the Claude Agent SDK; its AgentCore driver is on the roadmap.

Managed agent cloud · Google Cloud

Gemini Enterprise Agent Platform

Google Cloud's agent platform, the April 2026 successor to Vertex AI, with Agent Runtime (formerly Agent Engine), low-code Agent Studio and the open-source ADK.

Where it is strong

Broad governance tooling (agent identity, registry, gateway, evaluation) and enterprise controls such as VPC-SC, CMEK and data residency; 200+ models including Claude.

How Agent Workspace differs

A Google Cloud managed service whose first-party framework is ADK. Agent Workspace keeps the Claude Agent SDK as the loop and runs outside any one cloud.

Managed agent cloud · Azure

Microsoft Foundry Agent Service

A managed Azure platform with prompt agents run by Foundry and hosted agents that run your own framework, including the Anthropic Agent SDK, in a container.

Where it is strong

Deep Microsoft integration: per-agent Entra identity, RBAC, content safety, private networking, and publishing to Teams and Microsoft 365 Copilot.

How Agent Workspace differs

Foundry hosts the agent on Azure. Agent Workspace gives the same Claude Agent SDK a self-hosted control plane, and can still use Azure OpenAI as its model.

Managed agent cloud · beta

OpenAI Agents API

The Codex harness offered as an OpenAI-managed API, with OpenAI-hosted or self-hosted execution environments. The open-source Agents SDK (MIT) is separate; the visual Agent Builder shuts down on 2026-11-30.

Where it is strong

The same harness that runs OpenAI's Codex, with managed durable sessions and compaction, and an open-source SDK in Python and TypeScript.

How Agent Workspace differs

OpenAI runs the orchestration, with US data residency only today. Agent Workspace runs the Claude Agent SDK loop inside your infrastructure.

Deployment platform

LangSmith Deployment

Formerly LangGraph Platform: an orchestration runtime for agent workloads, deployable as cloud, BYOC, hybrid or self-hosted, which also deploys Claude Agent SDK agents.

Where it is strong

A mature open-source orchestration library with integrated tracing and evaluation, and flexible topologies including self-hosted Kubernetes.

Self-hosting and BYOC need the Enterprise plan and a licence key. Agent Workspace is Apache-2.0 end to end and adds a non-developer admin UI.

Visual builder

Dify

An open platform for building agents, workflows and chatbots on your own data, published as web apps or APIs, as Dify Cloud or a self-hosted Community Edition.

Where it is strong

Fast visual building of agents, workflows and RAG apps for non-developers, with a plugin marketplace and a free cloud plan.

How Agent Workspace differs

Dify runs its own agent node, not the Claude Agent SDK, under a modified Apache 2.0 licence with multi-tenant and branding conditions. Agent Workspace has no canvas or RAG by design.

Honestly

Where Agent Workspace is behind.

A comparison that only lists wins is an advertisement. These are the gaps you should weigh.

⚠No managed-cloud sandbox has a live isolation proof yet.
The hyperscalers ship microVM or VM isolation per session today; here, Docker is the verified default and Kubernetes is partially verified.
⚠You operate it.
Five services in production, with upgrades and backups that a managed cloud would do for you.
⚠TypeScript only.
The SDK and CLI are TypeScript; several alternatives ship SDKs in five or more languages.
⚠No canvas, no RAG, by design.
Teams who want visual workflows or a vector store will find them in Dify or n8n, not here.
⚠Non-Claude models run in compatibility mode.
Not every provider declares prompt caching or thinking, and the agent editor warns when the chosen model lacks prompt caching.
⚠Young.
No published customer references yet, and some features, such as public runnable agent links and stdio connectors, are switched off until they are ready.
