backend/ask.ts
// runAndRead and parseCitations are the manual-search tutorial's own helpers, not SDK exports
export async function askManual(aw, agentId, question, sessionId?) {
  const reading = await runAndRead(aw, agentId, { prompt: question, sessionId: sessionId ?? null });
  const read = new Set(
    reading.toolCalls
      .filter((call) => toolIs(call.name, 'read_section') && !call.isError)
      .flatMap((call) => parseCitations(call.output ?? '').map((citation) => citation.raw)),
  );
  const citations = parseCitations(reading.answer);
  const unverified = citations.filter((citation) => !read.has(citation.raw));
  return { answer: reading.answer, citations, unverified,
           grounded: citations.length > 0 && unverified.length === 0, … };
}

      From laptop to production
      
Five commands. The same agent all the way through.

    

    

      
    
        
  1. Scaffold and run
    A starter project with an agent and a surface, running in one Node process with embedded PostgreSQL. No Docker.
    2. 
        
  2. Talk to it
    Interactive aw chat streams the answer with a line per tool call, so you see what the agent did, not just what it said. -p prints only the answer.
    3. 
        
  3. Score it
    aw eval runs evals/<agent>.yaml and stores the score. A thumbs-down from a real user becomes a new case with aw eval add-case.
    4. 
        
  4. Version and promote
    aw push --yes saves a version. On aw dev, aw promote moves production to it only if the score clears minEvalScore; aw rollback moves it back.
    5. 
        
  5. Deploy
    aw deploy production --plan shows what will change; --yes applies it to a single VM or Cloud Run.
    6.

      FAQ
      
Questions buyers ask first.

      
Something else? Ask us.

    

    

      
Is this another agent framework?
No. The Claude Agent SDK runs the agent loop, unchanged. Agent Workspace stores what an agent is, secures its credentials, launches it in the sandbox you chose and streams what it did. Every setting in the UI is an SDK option.

      
Does any data leave our infrastructure?
The control plane, runner, sandboxes, database and object storage all run where you deploy them. The only outbound traffic an agent needs is to the model provider you configure, through the gateway, and the network policy of each runtime decides the rest.

      
Can we use Azure OpenAI or OpenAI instead of Claude?
Yes, through the Anthropic-compatible gateway. It is a compatibility mode, not an equivalent: each provider adapter declares what it supports (Azure OpenAI declares neither prompt caching nor thinking), and the agent editor warns when the chosen model lacks prompt caching. See compatibility.

      
Which sandboxes are production-ready today?
Docker is the recommended runtime for self-hosting and is fixture-verified. The sandboxed-process and Kubernetes drivers are implemented; Kubernetes lifecycle is partially verified. Azure Container Apps sessions and Cloud Run are implemented but not live-verified, and the rest are on the roadmap. The product disables what is not ready and says why.

      
Do we need Kubernetes?
No. A laptop needs one Node process. A single VM runs five components from one Compose file. Kubernetes is there when many teams need stronger isolation.

      
What happens if we stop using it?
You keep everything. Skills are SKILL.md folders, agents are TypeScript files or SDK options, connectors are MCP servers. Nothing is stored in a proprietary format.

      
Is there RAG or a vector database?
Deliberately not. Agents read workspace files with the SDK's own file tools and reach your systems through MCP connectors. Fewer moving parts to operate.

      
How do we buy it?
The SDK and CLI packages are published on npm. For a deployment, the Helm chart and support, book a demo with INDX.
